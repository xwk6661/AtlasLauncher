## 第一部分 · Minecraft-AIO 的设计解析

### 1.1 它反转了什么

传统启动器的组织中心是**版本 / 整合包**：用户先选版本，再启动，再进主菜单，再挑存档。
AIO 把组织中心换成**地图存档**：

| 维度 | 传统启动器（HMCL / PCL2 / Prism） | AIO |
| --- | --- | --- |
| 组织中心 | 游戏版本 / 整合包 | **地图存档** |
| 操作路径 | 选版本 → 启动 → 主菜单 → 单人游戏 → 选存档 | 点地图卡片 → 进图 |
| 版本概念 | 用户显式管理 | **对用户隐藏**，由解析器推断 |
| 失败成本 | 启动失败，重来 | **地图坏档**（不可逆） |

这个反转带来一个连锁后果：**版本从"用户选择"变成"程序推断"**，而推断错了会毁存档。
所以整个工程的重心不在 UI，而在「版本判定 + 不可逆操作的闸门」。这是理解 AIO 所有设计的钥匙。

### 1.2 三条硬约束（决定了架构）

| 约束 | 含义 | 架构影响 |
| --- | --- | --- |
| **C1 不坏档** | 绝不用高于地图原生版本的客户端打开存档。DFU 升档单向不可逆 | 必须有置信度 + 人工确认兜底；实例必须物理隔离 |
| **C2 机制 100% 还原** | CTM/RPG 依赖命令方块时序、红石更新顺序、怪物 AI | 逻辑必须跑在地图原生版本的**集成服务端**上，不能用协议层翻译 |
| **C3 空间与等待可控** | 装 20 个版本不能占 20GB；点地图不能等 20 秒 | 共享资源池 + 实例沙箱 |

C1 是红线，冲突时优先保 C1；C3 可以妥协。AIO 明确否掉了「一个高版本核心 + ViaVersion 通吃」这条路
（1.13 扁平化 / 1.16~1.20 数据包 / 1.20.5 物品组件化 三次语义断裂，DFU 只升区块不翻译命令）。

### 1.3 空间账：为什么必须"共享池 + 沙箱"

一个"版本"其实是四层解耦结构：

| 层 | 体积 | 复用性 |
| --- | --- | --- |
| `versions/<ver>/`（核心 jar + json） | 5~30 MB | **不可复用**，这才是真正的差异化文件 |
| `libraries/`（Maven 依赖） | 200~500 MB | 高度复用 |
| `assets/`（SHA-1 内容寻址） | 600 MB~1 GB | 完全复用（天然去重） |
| Java 运行时 | 150~300 MB/代 | 按代际复用 |

结论：不是发明共享机制，而是**每个实例一份 `--gameDir`，所有实例共享同一份 assets/libraries/versions**。
空间成本从 O(版本数 × 全量) 降到 O(版本数 × 20 MB)。

### 1.4 四条流水线（原理）

**① Archive Sniffer（压缩包嗅探）**
作者打包习惯千差万别（根目录直放、套三层中文文件夹、材质包放同级）。做法是**免解压列目录** →
找以 `level.dat` 结尾的条目锚定存档根 → 定向解压**只有那一棵子树** → 顺带嗅探材质包（`pack.mcmeta` /
文件名含"材质"/`resources.zip`）、随包模组、README 文本（供版本判定兜底）→ 写 `options.txt` 启用材质包。

**② Version Detector（三级判定）**

| 级别 | 依据 | 置信度 |
| --- | --- | --- |
| L1 精确 | `Data.Version.Name` / `Data.Version.Id` / `DataVersion` 命中对照表 | HIGH |
| L2 旁证 | 压缩包名、存档目录名、README 里的版本号（按来源权重 × 出现次数） | MEDIUM |
| L3 兜底 | Anvil/McRegion 容器版本（19133/19132）+ `BorderSize` / `entities/` / `players/` / `datapacks/` 结构特征 | LOW |

- 无版本字段时代（1.7.10 / 1.8.9）：`version=19133` + `BorderSize` → 1.8.x；无 `BorderSize` → 1.7.10 或更早。
- **26.x 的新布局**（`dimensions/<ns>/<dim>/region`）且无版本号 → **直接拒绝**，不猜（否则会被判成 1.8.9，等于不可逆降级）。
- **冲突裁决**（真实案例：`Version.Name=1.19.2` / `DataVersion=1.19.1`）：外部旁证 → `DataVersion` → 取最低；跨主次版本号则降为 MEDIUM 强制人工确认。
- **`unknown` 一律拒绝导入**。宁可让用户多点一步，也不赌。

**③ Provisioner（环境补齐）**
幂等：Java 大版本映射（≤1.16.5 → 8，1.17~1.20.4 → 17，≥1.20.5 → 21）→ 版本核心 + 依赖库 + 资源（自研下载器，停滞超时而非总时长超时）→ 加载器（Forge 官方安装器 / Fabric meta / OptiFine 只作为 Forge 模组）。
进度条用**引擎算的字节级刻度**，单调不减，界面只显示不计算。

**④ Direct World Entry（跳主菜单，双轨）**

| 轨道 | 版本 | 实现 |
| --- | --- | --- |
| A | ≥1.20 | `--quickPlaySingleplayer <world>`，零组件 |
| B | ≤1.19.4 | `-javaagent` 注入 ASM，钩主菜单初始化 → 反射调"进入存档" |

Agent 的**全部类名/方法名由参数传入**（`menu=` / `launch=` / `saveClass=` / `stopClass=` …），换版本只换参数、jar 不重编译。
参数由符号解析器产出：**官方 ProGuard 映射（1.14.4+）/ 字符串指纹（全版本）/ 人工微字典**三条来源合并，
每个候选都必须回 jar 里校验「类 + 方法 + 描述符」存在，校验不过就 `unresolved`，**绝不猜**。

### 1.5 最容易被忽略的一条：安全退出

AIO 的实测结论（S2）是：**主菜单出现时，退出保存还没开始**——此时杀进程会丢最多一个自动保存周期。
所以退出判定不是"看到主菜单"，而是：

> `saveAllWorlds` 的每个 RETURN 点（且必须是**退出请求之后**的保存，周期自动保存不算）
> **且** 主菜单已出现（或玩家主动发起）→ `EXIT_SAFE` → 才允许结束进程

`stopServer` 入口也要钩：玩家自己点 "Save and Quit to Title" 与启动器发起退出走同一套判定，只是 `by=launcher|player`。
对照组实验：主菜单即杀，退出保存 0/2；正解 6/6。

### 1.6 UI 逻辑（当前 Web/Electron 画廊）

**骨架**：单窗口 + 顶部菜单栏（地图 / 大厅 / 导入 / 环境 / 设置 + 搜索框 + 主题切换）+ 底部状态栏（计数）。
视觉照 Prism 取样，但配色**全部走语义令牌**（`--bg` / `--surface` / `--text-2` / `--sel`），
早期散着 106 个硬编码色号是反面教材；亮/暗两套共用同一组变量名。

**主视图（地图页）三区**：

| 区 | 内容 | 关键约束 |
| --- | --- | --- |
| 左：分组网格 | 按**版本族**分组（1.7.x / 1.8.x / 1.12.x / 1.16.x …），瓦片 = 封面 + 原名 + 中文别名 + 版本 | 图标三档尺寸；封面走图床缩放（20 张列表解码内存 158 MiB → 2.98 MiB） |
| 右：详情栏 | 图标、版本依据、状态、体积、游玩时长、包名、评分/短评 | **只读**。中文名/评分/笔记的编辑、删除实例，全部收进「实例管理」，避免误点 |
| 底：状态栏 | 地图数 / 总游玩时长 / 当前作业 | 与日志抽屉联动 |

**交互规则（都是从坑里长出来的）**：

- **双击**图标直接进游戏；**右键**才有「进入 / 打开实例目录 / 复制包路径 / 删除（后移到实例管理）」。
- **导入闭环**：识别 → 确认弹窗（可改实例名与版本，证据可展开）→ 导入。
  HIGH 且未改版本时**不传** `--mc-version`，保证 `versionEvidence` 能回答"这个版本是谁定的"。
- **实例管理**是独立路由 `#instance/<id>`，四个页签：概览（属性 + 版本依据 + 图标）/ 前置（装/换加载器）/ 模组（平台搜索）/ 设置（按实例覆盖启动参数，每项一个"跟随全局"）。
- **脏标记闸门**：15 秒轮询 `/api/state` 时，正在编辑的表单不能被覆盖（判断 `input/textarea/select` 是否有焦点，**要排除按钮**——否则点"保存"后重绘被挡住，出现"保存了但仍有未保存改动"）。
- **日志抽屉**：SSE 流式；批量渲染（120ms 合并 + 只留 1500 行），否则游戏跑起来后启动器会抢 CPU。
- 服务层自己也做闸门：LOW 置信度、`launchBlockers` 在服务端拒绝，不靠前端禁用按钮。

**前后端分工**：前端不实现业务逻辑，导入/启动一律 spawn CLI；服务层只转发 + 流式回显。
这条对 Prism 的移植很关键——Prism 是单进程 C++，这个边界会变成「UI 层不直接干重活，一律交给 Task」。

### 1.7 能力与代价（AIO 自己承认的）

能跑：识别 / 导入 / 装环境 / 启动 / 跳主菜单 / 安全退出 / 画廊 / 实例管理 / 加载器与模组 / 大厅。
没做：**可分发安装包**、`import` 的解压进度、1.17~1.19 的 `doWorldLoad`、Fabric 进图实跑、微软登录（只有离线档案）。

技术债清单里有一条特别值得 Prism 借鉴：**启动器内下载在 v0.24 被整条撤除**——分享页的 Cloudflare 只认可见浏览器，
为了过它试过七种"藏窗口"方案全失败。结论：**下载一律交系统浏览器**。

## 第二部分 · Prism Launcher 现有能力盘点

> 结论先说：**Prism 已经具备"半张地图启动器"**，甚至有两处是 AIO 手写的同款能力。

### 2.1 直接可复用（不用改代码）

| 能力 | Prism 里的实现 | 对应 AIO 的什么 |
| --- | --- | --- |
| **从 zip 里读世界 + 定向解压** | `minecraft/World.cpp`：`readFromZip()` 扫条目找 `level.dat` 并记下 `m_containerOffsetPath`；`install(to, name)` 用 `MMCZip::extractSubDir` 只解那一棵子树 | §5.4.1 Archive Sniffer 的核心两步，**已经写好了** |
| 归档格式 | `archive/ArchiveReader`（libarchive，`archive_read_support_format_all` + `filter_all`：zip / 7z / rar / tar / gz…） | AIO 用 7za + unrar WASM 拼出来的能力 |
| NBT | `libraries/libnbtplusplus`；`World::loadFromLevelDat` 已解析 `LevelName` / `LastPlayed` / `GameType` / `RandomSeed` | 只缺 `Data.Version.*` / `DataVersion` |
| 版本核心 + 依赖 + 资源 | `PackProfile` / `AssetUpdateTask` / `DownloadTask` | §5.4.3 Provisioner |
| Java 托管 | `AutoInstallJava` + `Launcher_ENABLE_JAVA_DOWNLOADER` | 同款 |
| 实例生命周期 | `InstanceTask` / `InstanceStaging` / `VanillaInstanceCreationTask` / `InstanceList::wrapInstanceTask` | AIO 自己写的"沙箱构建" |
| **直连存档** | `MinecraftTarget::world` + `MinecraftInstance::processMinecraftArgs()` → `--quickPlaySingleplayer`；`JoinWorldOnLaunch` 设置项在启动时自动装配 target（`MinecraftInstance.cpp:1169`） | §5.4.4 轨道 A **已经实现** |
| `-javaagent` | `VersionFile::agents`（`Agent{library, argument}`）+ `LaunchProfile::applyAgent`；实例级还有 `JvmArgs`（追加，不替换默认参数） | Agent 注入通道现成 |
| 世界列表 UI | `ui/pages/instance/WorldListPage`（列存档、算大小、支持"启动时进入该世界"） | 详情栏"世界"部分 |
| 模组 / 加载器 | `modplatform/modrinth`、`modplatform/flame`、`InstallLoaderDialog` | §24 加载器与模组 |
| 多页窗口骨架 | `PageContainer` + `BasePage` + `InstanceWindow`（左页签 + 右堆栈 + 底部 启动/关闭 按钮） | 实例管理四页签 |
| 实例网格 | `ui/instanceview/InstanceView` + `InstanceDelegate` + `VisualGroup`（分组） | 画廊网格 |
| 主题 / i18n / 更新 / 打包 | `ThemeManager` + `ui/themes/*`、`translations/`、`updater/`、CMake `install` / CI | AIO 完全没有的那一层 |

### 2.2 需要新建（Prism 一行都没有）

| 缺口 | 为什么 Prism 没有 | 工作量 |
| --- | --- | --- |
| **三级版本判定 + 置信度 + 证据** | Prism 只把 level.dat 当"元数据显示"，从不需要"由存档反推该用哪个版本" | 中（逻辑可照抄，表可直拷） |
| **地图归档的完整嗅探** | `World` 只找第一个 `level.dat`，不认材质包 / 随包模组 / README 旁证；且 `readFromZip` 只在 `suffix()=="zip"` 时触发 | 低 |
| **导入即建实例的编排** | `InstanceImportTask` 是**整合包语义**（解析 `mmc-pack.json` / manifest），地图包不是整合包 | 中 |
| **地图画廊 UI** | 实例网格以"实例名 + 图标"呈现，没有封面、版本依据、置信度角标、只读详情栏 | 中（体力活） |
| **≤1.19.4 直连** | Prism 靠 `feature:is_quick_play_singleplayer` trait 判断；低版本没有这个 trait，`world` 会被**静默忽略**（`MinecraftInstance.cpp:784`） | 高（搬 agent） |
| **安全退出判定** | Prism 等的是**进程退出**，没有"存档已落盘"这个概念 | 中 |
| **地图大厅** | 无 | 中（网络 + UI） |
| **随包资源包注入** | Prism 有资源包管理 UI，但导入期不写 `options.txt` | 低 |

### 2.3 关键差异（会直接影响设计）

| 主题 | AIO | Prism | 结论 |
| --- | --- | --- | --- |
| 实例目录名 | UUID（v0.28 试过 `id8-slug`，v0.28.1 回滚） | `FS::DirNameFromString(实例名)` | **跟随 Prism**，不要为了 UUID 改 `InstanceStaging` |
| 元数据 | `map-meta.json` 唯一源 | `instance.cfg`(INI) + `mmc-pack.json`(JSON) | 新增 `map.json` 只放"地图特有"的，别重复版本/名称 |
| 版本名 | 存档里的 `Version.Name` 直接用 | 组件 id 必须能在 meta 版本表里命中 | 需要**归一化**（`1.16.5` vs `1.16.5-forge-36.2.39` vs 快照名） |
| 世界目录名 | 固定 `MapWorld` | 用户命名，`JoinWorldOnLaunch` 存目录名字符串 | 沿用 `MapWorld`（quickPlay / Agent 都吃字符串，中文路径有历史坑） |
| 进程模型 | 主进程 + CLI 子进程 + SSE | 单进程，启动走 `LaunchTask` 步骤链 | 事件流从"解析子进程 stdout"变成"解析 `LaunchTask` 日志行" |
| UI | Web（HTML/CSS/JS） | QWidget + .ui + QSS | 布局概念可平移，CSS 令牌要换成 QSS palette |

## 第三部分 · 三条路线与推荐

### 路线 A（推荐）：同一二进制，加一个"地图模式"主窗口

- `Application` 现有的 `showMainWindow()` 按设置/命令行决定起 `MainWindow`（实例网格）还是 `MapMainWindow`（地图画廊）。
- 复用同一个 updater、账号、Java、翻译、主题、实例系统。
- 代价：主窗口要写一套新的；实例网格作为"高级模式"保留，随时切回。

### 路线 B：新增独立 CMake target（`PrismMaps`）

Prism 的 CMake 是**单一可执行文件**（`add_executable(${Launcher_Name} ...)` 汇总所有源），没有拆静态库。
做独立二进制要么复制一份 source 列表、要么先做 `launcher_core` 静态库重构。后者是对的，但那是上游级别的手术，
会持续和上游冲突。**建议等 M3 之后再评估**（先出产品，再谈拆分）。

### 路线 C：另开 fork，把 `MainWindow` 直接改成地图画廊

改动面最小、最快出形态，但丢掉"实例网格"这个 Prism 最有价值的能力，且上游同步会非常痛。
适合"只做地图、不打算跟上游"的一次性产品。

### 被否掉的路线：在 Prism 里嵌 Node 跑 AIO 的 `launcher/src`

技术上能做（`QProcess` 起 node，把 `--json` 输出喂给 UI）。但：

1. 分发要多带一个 Node 运行时（或用户机器上得有 node）；
2. 两套错误边界（Node 崩溃 / 端口占用 / 进程残留），AIO 自己在 Electron 上已经踩了一整页坑；
3. 它解决的是"环境安装"，而这块 Prism 做得比它好（它自己在 v0.2 就退回 `@xmcl` 了）。

**唯一值得从 AIO 搬的运行时资产是 Java Agent 和符号表**，那本来就是 Java，跟 C++ 侧只通过命令行参数和日志交互。

## 第四部分 · 结论

1. **可行**。地图导入的硬骨头（归档嗅探 + 定向解压 + NBT）Prism 已经有 60%，1.20+ 直连甚至已经实现。
2. **真正的增量在三个地方**：版本判定（中）、旧版本 Agent（高，但可整包复用）、以地图为中心的 UI（中，体力活）。
3. **风险主要在工程之外**：GPL-3.0 传染、符号表覆盖面、以及网络（Qt 没有 QUIC，见 02 的 R2）。
4. **不要做的事**：不要重写符号解析器到 C++；不要为 UUID 目录名改 `InstanceStaging`；不要做启动器内下载；不要让"一个高版本通吃"的念头复活。
