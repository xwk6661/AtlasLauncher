# 02 · 架构与路线图

> 目标：在 **不改 Prism 既有语义** 的前提下，把"地图"变成一等公民。
> 原则：**新代码只放新目录；对既有文件只做加法**（改签名 = 未来每次 rebase 都要打一次架）。

---

## 1. 总体结构

**新代码全部在 `launcher/maps/`**（33 个 .cpp + 37 个 .h，15,435 行），对既有文件只做接线级加法：

```
                    ┌───────────────────────────────────────────────┐
                    │ 既有界面（只接线，不改语义）                    │
                    │ MainWindow 操作栏 · 实例「信息」页 · 设置页     │
                    └───────────────┬───────────────────────────────┘
                                    │ 只发命令 / 只读结果
                    ┌───────────────▼───────────────────────────────┐
                    │ launcher/maps/（新增）                         │
                    │ 识别 → 导入 → 启动 → 大厅 → 界面 → 设置        │
                    └───────────────┬───────────────────────────────┘
        ┌───────────────┬───────────┴───────────┬───────────────────┐
        ▼               ▼                       ▼                   ▼
  Prism 既有       quickboot.jar          HallAPI / BrowserFetch  ResourcePaths
  Instance/Launch  + 6 张符号表           （CTM 数据与封面）      （assets/libraries/java）
```

一句话：**界面只发命令 → `maps/` 做判断与编排 → 底层复用 Prism 的实例/启动/下载，
或调用 jar、浏览器通道、资源路径解析这三样独立能力。**

> 唯一"跨模块"的新增是 `launcher/ResourcePaths.{h,cpp}`：资源目录要能被 Prism 各处读到，
> 放在 `maps/` 里不合适（见 §2.3）。

## 2. 磁盘与新文件

### 2.1 实例目录（导入一张地图之后）

```
instances/<map-id>/                    # map-id = FS::DirNameFromString(地图名)
├── instance.cfg                       # Prism 既有：name / iconKey / JoinWorldOnLaunch=MapWorld / 内存 / Java
├── mmc-pack.json                      # Prism 既有：net.minecraft=1.16.5 (+ net.forge=…)
├── map.json                           # ★ 新增：地图特有元数据（见 2.2）
├── icon.png                           # 从存档 icon.png 提升的实例图标
└── .minecraft/
    ├── saves/MapWorld/                # 定向解压，目录名固定英文
    ├── saves/MapWorld_2/              # 一包多世界时的次存档
    ├── resourcepacks/<pack>.zip       # 随包材质包
    ├── mods/*.jar                     # 随包模组
    └── options.txt                    # 合并写入 lang / resourcePacks，不覆盖其它键
```

**为什么世界目录叫 `MapWorld`**：`--quickPlaySingleplayer` 与 Agent 参数都吃"目录名字符串"，
老版本对中文/特殊字符路径有解析 Bug（AIO §5.3 的结论，实测过）。英文名是最廉价的兼容手段。

### 2.2 `map.json`（单一职责：只放"地图特有"的东西）

```json
{
  "schema": 1,
  "title": "盘灵古域",
  "alias": "Panilla",
  "archive": {
    "path": "E:/Topic-Minecraft/盘灵古域v1.2.rar",
    "size": 734003200,
    "sha1": "…",
    "libraryCopy": "E:/MapLibrary/盘灵古域v1.2.rar"
  },
  "version": {
    "mcVersion": "1.7.10",
    "confidence": "LOW",
    "evidence": ["Anvil", "FML", "文件名:1.7.10"],
    "decidedBy": "detector"          // detector | user | archive
  },
  "worlds": [{ "folder": "MapWorld", "sourceRoot": "解密地图v2/saves/MyWorld/" }],
  "loader": { "type": "forge", "version": "10.13.4.1614" },
  "packs": ["map_pack.zip"],
  "mods": ["CustomNPCs.jar"],
  "stats": { "playSeconds": 3420, "lastPlayed": "2026-10-31T10:30:00Z", "lastExit": "safe" },
  "importedAt": "2026-10-31T10:00:00Z"

```

**为什么不塞进 `instance.cfg`**：INI 表达不了数组与证据链，而且 `instance.cfg` 是 Prism 的领域
（`INISettingsObject` 有类型与默认值的语义）。**也不重复 Prism 已有的字段**：版本在 `mmc-pack.json`、
显示名在 `instance.cfg` 的 `name`、启动参数在 `instance.cfg`。`map.json` 只回答"这张图是从哪来的、凭什么判成这个版本"。

> 读写用一个薄封装 `MapMeta::load(instanceRoot)` / `MapMeta::save()`，全工程只此一处碰这个文件。

### 2.3 三份公共资源（assets / libraries / java）

除实例目录外，还有三份**跨实例共享**的资源，位置由 `launcher/ResourcePaths` 统一决定：

| 目录 | 内容 | 默认位置 |
| --- | --- | --- |
| `assets` | 游戏资源（音效、语言、贴图索引）；`indexes/` + `objects/` | `<数据目录>/assets` |
| `libraries` | Maven 布局的 Java 类库（LWJGL、authlib…） | `<数据目录>/libraries` |
| `java` | Mojang 官方 Java 运行时（1.21 会拉 `java-runtime-delta`，400+ 文件） | `<数据目录>/java` |

设了全局设置 `SharedResourceDir` 后，三者改为 `<共享目录>/assets|libraries|java`；
**用真路径而不是目录联接**：迁移就是搬文件（同盘 `rename`，跨盘复制后删源），
迁移后启动器直接读新位置。代价是改完要重启（绝对路径在启动时进了 meta cache）。

改掉的写死点：meta cache 的两个 base、`AssetsUtils` 两处、`AssetUpdateTask` 读索引、
`MinecraftInstance::librariesPath()` 与启动脚本的 `assets_root`、`Application::javaPath()`。

## 3. 模块设计

### 3.1 `maps/MapArchiveScanner` —— 免解压嗅探

```cpp
struct MapScanResult {
    QString archivePath;
    QList<WorldCandidate> worlds;      // worldRoot / levelDat(原始字节) / hasIcon
    QStringList resourcePacks;         // 包内路径
    QStringList bundledMods;
    QString readmeText;                // 供 L2 旁证
    qint64 archiveBytes = 0;
    QStringList warnings;
};

class MapArchiveScanner {
public:
    static Result<MapScanResult> scan(const QString& archivePath, std::function<bool(int)> progress);
};
```

实现要点（全部基于现成的 `MMCZip::ArchiveReader`）：

1. `parse()` 单趟遍历，**不解压**，只记名字与大小；
2. 收集所有以 `level.dat` 结尾的条目 → 每个的父路径即候选 `worldRoot`；
3. 对每个候选读一次 `level.dat`（`File::readAll()`，几十 KB）→ 走 NBT；
4. 材质包判定优先级（照 AIO §6.3）：根目录 `resources.zip` > 内含 `pack.mcmeta` 的 zip > 文件名含 `resource/材质` > 体积启发；
5. `mods/*.jar`、`*.txt|*.md`（取前 64 KB）一并带回；
6. 只保留"看起来是地图"的结果；一个都没有 → `Error("这个包里没有 level.dat")`。

> 需要的既有改动只有一处：`World::repath()` 现在只在 `suffix()=="zip"` 时走 zip 分支
> （`launcher/minecraft/World.cpp`），要放宽成"是文件且 `ArchiveReader` 能打开"。

### 3.2 `maps/MapVersionDetector` —— 三级判定

```cpp
enum class Confidence { High, Medium, Low, Unknown };
struct VersionGuess {
    QString mcVersion;          // 归一化后的 meta 组件版本，可直接塞进 mmc-pack
    Confidence confidence = Confidence::Unknown;
    QStringList evidence;
    QString suggestedLoader;    // vanilla | forge | fabric | neoforge
};

class MapVersionDetector {
public:
    static VersionGuess detect(const LevelDatFacts& facts,
                               const QString& archiveName,
                               const QString& readme,
                               const MapLayoutFacts& layout);
};
```

- `LevelDatFacts`：从 NBT 抽 `Version.Name` / `Version.Id` / `DataVersion` / `version`(19133|19132) /
  `LevelName` / `FML`|`fml` / `WasModded` / `DataPacks`。**这是对 `World::loadFromLevelDat` 的唯一扩展**（加字段，不改行为）。
- 判定顺序与权重照 AIO §6.2：精确字段 → DataVersion 表 → 文本旁证（文件名/README）→ 结构特征。
- 冲突裁决：外部旁证 → `DataVersion` → 取最低；跨主次版本降 MEDIUM。
- **新布局（26.x）无版本号 → 直接 `Unknown`**，理由是"1.8.9 客户端打开会按旧格式回写 = 不可逆降级"。
- `deriveRange`（可选增强）：`DataVersion` 落在两个已知版本之间时，取**不高于**它的最近版本（保守原则）。

`DataVersion` 表：把 AIO 的 `launcher/src/version/dataversion-table.json`（67 个正式版 / 483 条目）
原样拷进 `launcher/resources/dataversion.json`，随二进制发布，**只读不写**。
运行时用 `QJsonDocument` 一次性加载成 `QHash<int, QString>` + `QHash<QString, int>`，查表 O(1)。

### 3.3 `maps/MapImportTask` —— 建实例（继承 `InstanceTask`）

```cpp
class MapImportTask : public InstanceTask {
    Q_OBJECT
public:
    MapImportTask(QString archivePath, MapScanResult scan, VersionGuess guess, QString displayName);
    void executeTask() override;
protected:
    Result<> createInstance();     // MinecraftInstance + mmc-pack + instance.cfg
    Result<> extractWorld();       // 只解 worldRoot 子树 → saves/MapWorld
    Result<> deployPacks();        // 材质包 / 模组 / options.txt 合并
    Result<> writeMeta();          // map.json + 图标
};
```

关键决定：

- **不写新的实例构建器**。`InstanceTask` 已经给了 `m_stagingPath`（`InstanceStaging` 分配的临时目录）、
  `m_globalSettings`、`downloadFiles(inst)`，提交由 `InstanceList::commitStagedInstance()` 完成。
  照 `VanillaCreationTask` 的样子做即可：`PackProfile::buildingFromScratch()` +
  `setComponentVersion("net.minecraft", version, true)` [+ 加载器组件] + `saveNow()`。
- **解压用 `MMCZip::extractSubDir`**（`World::install` 内部就是它），天然只解一棵子树。
- **`options.txt` 用"合并"不用"覆盖"**：只改 `lang` / `resourcePacks` 两行，其余行原样保留
  （重装地图时尤其重要，玩家改过的按键/灵敏度不能被冲掉）。
- **失败要能回滚**：staging 目录由 Prism 管，任务 `emitFailed` 后 `InstanceStaging` 会清掉；
  但"已写进 `saves/` 的半截世界"要自己删——**先解到 `.tmp-world/`，校验 `level.dat` 能解析后再改名**。

### 3.4 `maps/MapLaunchPrep` —— 启动前的统一准备点

```cpp
struct Plan {                  // 判出来给下游用，也用来打一行可检索的日志
    Track track;               // QuickPlay / Agent / Plain
    bool autoEnter, closeOnQuit;
    int  enterDelay;
    QString world, reason;     // reason 会原样进日志：Map launch plan: …
    bool applicable;
};

class MapLaunchPrep {
public:
    static Plan prepareForLaunch(MinecraftInstance* inst, const QString& requestedWorld = {});
    // 1) 选轨道：trait "feature:is_quick_play_singleplayer" 有 → QuickPlay，无 → Agent
    //    **traits 这一刻可能还没解析**（启动瞬间组件未加载）→ 退一步读 meta 里该版本的 traits；
    //    连 meta 都读不到就只写世界名、不注入 Agent，让游戏按自己的 trait 决定（详见 06 §12 #62）
    // 2) QuickPlay：settings["JoinWorldOnLaunch"] = "MapWorld"
    //    Agent：AgentBootstrap::configure(inst, symbols, worldName)
    // 3) 记下"期望安全退出"，供退出后回写 stats.lastExit
};
```

轨道判定**只认 trait，不认版本号**（`MinecraftInstance.cpp:784` 就是这么写的；写死 `>=1.20` 会在
Forge/NeoForge 派生版本上出错）。

轨道定下来之后，`Application::launch()` 还会按 `Plan` 挂两个与轨道无关的旁路：

| 旁路 | 挂载条件 | 作用 |
| --- | --- | --- |
| `MapQuitWatcher` | `autoEnter && closeOnQuit` 且不是 Agent 轨道 | 1.20+ 关游戏（见 §4.2） |
| `MapWindowFocus` | `autoEnter` | 把前台交给游戏窗口，规避 quickPlay「无焦点抓鼠标」缺陷（见 §4.2） |

### 3.5 `maps/AgentBootstrap` —— ≤1.19.4 直连

```cpp
class AgentBootstrap {
public:
    static bool hasSymbols(const QString& mcVersion);          // resources/agents/symbols/<ver>.json
    static Result<QString> buildAgentArg(MinecraftInstance* inst, const QString& world);
    static void attach(LaunchTask* task, QObject* ctx);        // 挂 LogModel::rowsInserted
};
```

参数照 AIO 的契约（`k=v,k=v`，全部由符号表生成，jar 不重编译）：

```
-javaagent:<data>/agents/quickboot.jar=world=MapWorld,menu=…,menuDesc=…,mc=…,launch=…,launchDesc=…,
saveClass=…,saveMethod=…,saveDesc=…,stopClass=…,enterDelay=1,haltOnSafe=1,log=<run>/agent.log
```

- 注入方式：写实例的 `JvmArgs`（`JvmArgs` 是**追加**参数，见 `BaseInstance::extraArguments()`，
  不会顶掉内存/GC 等默认参数）。
- **符号表不实时解析**。用 AIO 的 `symbols` 命令离线性生成 `symbols/<version>.json`，
  作为构建产物的资源文件随包发布；命中不了就 `Unsupported`，**降级为普通启动并明确提示**
  （等价于 AIO 的"R5 兜底"）。
- 事件流：`LaunchTask::getLogModel()` 是 `QAbstractListModel`，挂 `rowsInserted` 逐行匹配
  `[mcml-agent] ENTER_WORLD_OK / SAVE_DONE (quit save) / MENU_2_SEEN / EXIT_SAFE / EXIT_UNSAFE_TIMEOUT`。
- **Forge 的坑要原样继承**（AIO §26 / §5.4）：FML 会把 `System.out` 重定向进 log4j，
  stdout 从那一刻起收不到事件；所以 Agent 必须**同时写自己的日志文件**，宿主 400ms 轮询 tail。
  另外 Agent 参数要落到**系统属性**（`mcml.agent.args`），防止 LaunchClassLoader 加载出第二份副本读到空配置。

### 3.5.1 `maps/AgentBootstrap` 的第二个用途 —— 1.20+ 跳过「实验性设置」确认页

1.20+ 没有符号表、也不注入 Agent（直连靠 quickPlay）。但地图自带**改过世界生成的数据包**时，
原版在加载前会弹一次「不支持使用实验性设置的世界 / 创建备份并加载 / 我知道我在做什么」，
quickPlay 就停在那一页 —— 这一页不处理，"点开就进图"永远差一步。

闸门只有一个方法：`WorldOpenFlows.askForBackup(LevelStorageAccess, boolean customized,
Runnable loadLevel, Runnable onCancel)`。它不加载世界，只负责弹确认页；玩家点
「我知道我在做什么」最终执行的就是 `loadLevel`。所以补丁的做法是**把这个方法体整体换成
`loadLevel.run(); return;`** —— 不动 `level.dat`、不动数据包、不建备份。

| 要点 | 做法 |
| --- | --- |
| 混淆名逐版本变化 | 随包 `resources/agents/introskip.json`，由 `tools/introskip-agent/gen_table.py` 从 Mojang 官方 `client_mappings` 离线生成（1.20–1.21.5 共 13 个版本） |
| 1.20~1.20.2 签名不同 | 那两个版本是 `(Screen, String, boolean, Runnable)`，`loadLevel` 在 local 4；表里用 `index` 字段区分 |
| 与 Forge/Fabric 共存 | Agent 自带的 ASM 重定位到 `atlas/introskip/shaded/asm`，不占用 `org/objectweb/asm` |
| 注入时机 | `MapLaunchPrep` 把 `-javaagent` 放进实例的运行时属性 `mapsJavaAgents`，由 `MinecraftInstance::extraArguments()` 追加到 java 命令行；**不写 `JvmArgs`**（那是 override 设置，未开覆盖时读不到）；**与轨道无关**，traits 未解析的冷启动也会注入 |
| 失败了怎么办 | 任何一步失败只记警告、不挡启动 —— 最坏退化成原版那样多点一次 |

> 设置项 `MapSkipExperimentalPrompt`（默认开，实例可覆盖）。日志：实例目录下 `introskip.log`。

### 3.6 `maps/HallAPI` —— 地图大厅

```cpp
class HallAPI : public QObject {
    Q_OBJECT
public:
    void search(const HallQuery& q);      // maps_search_view：搜索/排序/筛选
    void detail(const QString& slug);     // maps 表：简介 / 11 项属性 / 评论
signals:
    void searchDone(QList<HallItem>);
    void detailDone(HallDetail);
    void failed(QString humanReason, QString techDetail);
};
```

- 查询走 `NetJob`，`select=*`（**不要写死列名**，站方改列是常态——AIO 为这个吃过 400）。
- endpoint 可配置（设置项 `MapHallEndpoint`），默认 CTMMaps 的 Supabase 基地址
  （`https://qtxjbukjyuylqjgiphxs.supabase.co`，见 AIO `src/hall/index.ts`）；
  anon key 是站点前端自带的公开值（受 RLS 约束只能读），放资源文件里，不写进仓库的其它地方。
- **不做启动器内下载**：`downloadUrl` 一律 `QDesktopServices::openUrl` 交系统浏览器
  （AIO §40：分享页的 Cloudflare 只认可见浏览器，七种"藏窗口"全失败）。
- 失败要给人话：分类（DNS / TLS 握手重置 / 超时 / 空结果）+ 技术细节折叠 + 重试按钮。

### 3.6.1 `maps/ModPresets` + `ModPresetDialog` —— 一键装模组预设

地图实例几乎都是 Vanilla。玩家想加模组，得先装加载器、再一个个搜、还要自己判断
哪个文件对应这个 MC 版本 —— 这条路上的每一步都能劝退人。预设把"选哪些模组"和
"选哪个文件"拆开：**玩家只决定要什么，版本由程序按实例现查**。

| 层 | 做什么 |
| --- | --- |
| `ModPresets` | `<数据目录>/mod-presets.json` 的读写；内置三套（Fabric 性能 / Fabric 实用 / Forge·NeoForge 性能）；`matchesLoader` 判断预设是否适用于某实例 |
| `ModPresetResolveTask` | 逐条查 `GET /v2/project/<slug>/version?game_versions=[..]&loaders=[..]`，优先 release，其次任意版本；一条失败不影响后面 |
| `ModPresetDialog` | 选预设 → 逐行显示解析到的版本 → 勾选 → 用 `ResourceDownloadTask` 批量装；另有「自己挑…」直接打开原生模组浏览器 |
| `ModPresetEditorDialog` | 预设编辑：一行一个模组（slug、显示名、备注三段，用竖线分隔），行首 `-` 表示默认不勾选 |

三条硬规则：

1. **不猜版本**。解析不到匹配文件就标红、取消勾选、不下载；绝不"拿个近似版本试试"。
2. **不动实例配置**。预设只往 `mods/` 放文件，不改 `mmc-pack`、不改 `map.json`。
3. **加载器缺失先问**。`ModPresetDialog::run()` 发现实例没有加载器时，先弹一句
   再用现成的 `InstallLoaderDialog` 装 —— 装完继续，不用退出重来。

> 入口两处：右侧地图卡片的「装模组预设…」、实例窗口「模组」页工具栏的「模组预设…」。
> 版本查询走 `BuildConfig.MODRINTH_PROD_URL`，与模组浏览器同一个域名；下载走
> `ResourceDownloadTask`，所以 Modrinth 元数据会跟着写入，之后能在模组页检查更新。

### 3.7 UI —— 融入原生，不另起模式

**不做独立地图模式，也不做单独的 ui/maps 目录**：地图相关的界面全部是 `maps/` 里的 widget，
由既有界面按需插入。

| 入口 | 落地 | 说明 |
| --- | --- | --- |
| 选中地图实例 | `MapInstanceBar` 插进**原生实例操作栏** | 中文名 / 版本徽章 / 置信度 / 评分 / 笔记 / 统计 / 世界下拉 / 「进入地图」；非地图实例整块隐藏 |
| 实例窗口「信息」页 | `MapInstancePage`（三个页签） | 简介（封面 + 基本信息卡 + 正文卡）/ 评论（`MapReviewCard`）/ 我的（三张卡） |
| 「添加实例」下拉 | `MapHallPage` | CTM 大厅：搜索 / 排序 / 系列·难度·长度·年份 / 封面列表 / 详情三页签 |
| 菜单「地图大厅…」 | `HallDialog` | 独立窗口形态，表格 + 详情 |
| 菜单「地图画廊…」 | `MapGalleryWindow` + `MapGalleryPage` | 次要入口，独立窗口 |
| 设置 | `MapPage`（全局「地图」）、`MapSettingsWidget`（实例「设置 → 地图」页签）、`MapResourcePage`（全局「资源」） | 地图启动行为、大厅通道、控制台页签、资源库 |

导入确认用 `MapImportDialog`（名称 / 世界 / 版本 / 加载器 / 证据 / 置信度红条 / 缺模组提示）。
主题一律走 `MapTheme.h`（`confidenceColor / starColor / mutedTextColor / cardStyle`），不写死颜色。

## 4. 两条主流程

### 4.1 导入

```
拖入 .zip/.rar/.7z（或菜单「导入地图」）
 1  MapArchiveScanner::scan               免解压列目录 → worlds[] / packs[] / mods[] / readme
 2  读候选 level.dat（NBT）                Version.Name / DataVersion / FML / LevelName
 3  MapVersionDetector::detect            三级判定 → 版本 + 置信度 + 证据
 4  ┬ Unknown → 结束，弹"无法确定版本"（可手选版本，记 decidedBy=user）
    └ 否则 → 确认对话框（名称/版本/加载器/风险提示）
 5  MapImportTask（InstanceTask）
      5.1 staging 目录里建 MinecraftInstance + mmc-pack + instance.cfg
      5.2 解 worldRoot → staging/.minecraft/saves/MapWorld（先 .tmp-world 再改名）
      5.3 材质包/模组落位 + options.txt 合并
      5.4 map.json + icon.png
      5.5 downloadFiles(inst)               版本核心/依赖/资源/Java（Prism 既有）
 6  InstanceStaging 提交 → 实例列表刷新 → 画廊插入卡片
```

失败点与处理：`5.2` 前任何一步失败都只需删 staging；`5.2` 之后失败要删掉半截世界目录
（这也是"先解到 `.tmp-world`"的原因）。

### 4.2 启动

```
双击卡片 → MapLaunchPrep::prepareForLaunch(inst, 世界名)
 ├ trait 有（1.20+）→ JoinWorldOnLaunch = "MapWorld" → LaunchController → --quickPlaySingleplayer
 └ trait 无（≤1.19.4）→ 有符号表？
        ├ 有 → JvmArgs 追加 -javaagent:… → 照常启动 → 挂日志监听
        └ 无 → 普通启动（停在主菜单）+ 顶部提示条："该版本不支持自动进图"

启动后（与轨道无关，看 Plan 的两个开关）：
  MapWindowFocus   每 250ms 找该进程的 GLFW 窗口，把前台交过去（只在启动器自己占前台时动手）
  MapQuitWatcher   300ms 核对一次「连的还是不是当前 LaunchTask」，变了就断开重连

轨道 A（1.20+）不注入 Agent，退出由「日志看门狗」补：
   MapQuitWatcher 监听 LaunchTask::gameLogLine
     「Stopping singleplayer server as player logged out」（离开存档）
     →「All dimensions are saved」（落盘完成）→ 给游戏窗口发 WM_CLOSE
     （8 秒未退才强制结束；10 秒等不到落盘标记也会关）

轨道 B（≤1.19.4）的 agent.log：
   ENTER_WORLD_OK  → 状态栏"游戏运行中 · 已进图"
   SAVE_DONE (quit save) → EXIT_SAFE → 回写 stats.lastExit="safe"
   EXIT_UNSAFE_TIMEOUT → 不杀进程，状态栏红字 + 日志定位
```

**两个实现上的约束**（都是踩出来的，详见 [06](06-变更记录.md)）：

- **世界名只能出现一次**。启动脚本会写 `worldName`，`NewLaunch.jar` 据此自己补
  `--quickPlaySingleplayer`；而 `processMinecraftArgs(session, nullptr)` 又会读
  `JoinWorldOnLaunch` 补一遍 → 命令行里出现两次，Minecraft 的 joptsimple 直接抛
  `MultipleArgumentsForOptionException`，窗口都来不及创建。所以脚本路径下要摘掉后者。
- **看门狗不能只在 `runningStatusChanged` 时连任务**。`LaunchTask::create()` 里
  `init()` 先 `setRunning(true)`，而 `LaunchController` 是拿到对象之后才写进 `m_launchProcess` ——
  信号到达时取到的是**上一次**那个已结束的任务（第一次启动时是 `nullptr`，靠重试躲过去了）。
  所以改成定时核对指针。

**安全退出策略**：`haltOnSafe` 建议默认 **1**（让 Agent 自己 `halt`）。
理由是 Prism 的 `LaunchTask` 只有"进程退出"概念，没有"落盘完成"概念；让 JVM 在确认落盘后自己退出，
比在宿主侧猜时机可靠。设置项保留 `0`（宿主 kill）给排障用。

## 9. 上游同步策略

1. 每期结束跑一次 `git rebase upstream/develop`，冲突预期只出现在 `CMakeLists.txt` 与 `MainWindow.{h,cpp,ui}`。
2. 新增的 `World` getter 用**默认参数 + 新方法名**，不改旧签名 → 上游改动 `loadFromLevelDat` 时冲突面最小。
3. 设置项集中在 `Application::registerSettings()` 的一段注释块里，方便定位。
4. 翻译文件不手改，走 `lupdate`。
5. 若最终要独立二进制（路线 B），此时再把 `launcher/` 拆出 `launcher_core` 静态库——**不要提前拆**。
