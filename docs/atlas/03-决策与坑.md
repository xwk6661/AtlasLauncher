## 1. 网络与阻断

### 1.1 `*.supabase.co` 被封的是 **SNI 字符串**，不是 IP

2026-11-01 逐条排除：

| 试法 | 结果 |
| --- | --- |
| DNS 解析 | ✅ 正常（Cloudflare `104.18.38.10` / `172.64.149.246`） |
| HTTPS 根路径 | ❌ `Connection was reset` |
| `--tls-max 1.2` / `--http1.1` | ❌ 一样 reset（不是 ALPN/TLS 版本） |
| 明文 `:80` | ❌ 同样 reset（不是"只掐 TLS"） |
| 换端口 8443 / 2053 / 2083 / 2087 / 2096 | ❌ 全 reset |
| 同一 IP、**SNI 换成 `api.modrinth.com`** | ✅ **200** |
| `https://www.ctmmaps.com/` | ✅ 200（站点本身没被封） |

结论：被封的是 `*.supabase.co` 这个 SNI。浏览器能过是因为 Chromium 实现了 ECH / GREASE；
Qt 在 Windows 走 Schannel，只能明文写 SNI，发出去就被 RST。

> 不要试图自己实现 HTTP/3：Qt 6.8 没有 QUIC，浏览器就在本机，借它更省事。

### 1.2 reset 是概率性的

同一条 REST / 图片 URL 实测约 **1/3 概率**被 reset。任何"一次请求定生死"的写法都会偶发失败：
重试必须放在**页面内**（XHR + 退避），而不是"失败就重开一个浏览器进程"。

### 1.3 浏览器通道的两个硬性参数

- **不能加防缓存参数**：PostgREST 对未知查询参数返回 `PGRST100 / unexpected param`（400），
  `?_r=1` 会让重试全灭；
- **`--disable-web-security` 必须有**：跨域图片画进 canvas 会 tainted，`toDataURL` 直接抛异常。
  用一次性空白 profile、只加载自己生成的临时页面，跑完即杀。

### 1.4 浏览器通道的三种失败必须分开报

| 现象 | 含义 | 处置 |
| --- | --- | --- |
| `stdout` 空、退出码 0 | 浏览器正常退出但**没干活**（自更新 / 已有实例接管 / 企业策略） | 换本机另一个浏览器（Edge → Chrome），别在同一个 exe 上耗预算 |
| `<pre>` 还是 `pending` | 页面没跑完（预算先到） | 加大 `--virtual-time-budget` 再来一次；用尽后明说"没跑完"，别说"没有返回内容" |
| 有 DOM、没有结果节点 | 页面结构 / URL 变了 | 报出 DOM 字节数 |

开发机"看着正常"可能只是本地大厅缓存遮住了网络（2026-11-15 的误判，[06 §85](06-变更记录.md)）。

### 1.5 元数据镜像导致的"列表更新失败"

`Connection closed` 常常不是代码问题，而是设置里 `MetaURLOverride` 指向了失效镜像。
排查：`atlas.cfg` 搜 `MetaURLOverride` → 清空 → 确认 `https://meta.prismlauncher.org/v1/index.json` 返回 200。

## 2. Windows / 工具链

1. **环境里同时有 `HTTP_PROXY` / `http_proxy` / `HTTPS_PROXY` / `https_proxy`** 时，
   `Enter-VsDevShell` 抛 `ArgumentException`（键冲突）。进 PowerShell 先清进程级变量。
2. **`bootstrap-vcpkg.bat` 失败**（`SetFileInformationByHandle error 0x5 拒绝访问`）：
   手动下载 `vcpkg.exe` 放进 vcpkg 根目录。
3. **rc / kernel32.lib 找不到**：VS 实例没注册 Windows SDK。解法是 overlay triplet +
   `VCPKG_ENV_PASSTHROUGH RC LIB INCLUDE PATH`（[02 §3](02-构建与运行.md)）。
4. **同一构建目录不能同时跑两个编译**：会互相锁 `.obj`（`C1083: Permission denied`）。
   杀毒扫新写出的 obj 也会造成随机 `Permission denied` —— 重跑一次即可；**默认并行度下更容易撞上**
   （一次能同时挂 5–8 个文件，目录其实可写）。要一次过就 `$env:CMAKE_BUILD_PARALLEL_LEVEL = "2"`
   再调 `build\run-configure.ps1`（2026-11-17 实测：默认并行 3 次里 2 次假失败，降到 2 全过）。
5. **Debug 的 `Q_ASSERT` 会 qFatal**：`SequentialTask::subTaskFailed` 对每个失败子任务都 `emitFailed`，
   两个同时失败时第二次撞上 `ASSERT_NEVER(!isRunning())`。Release 只记警告，上游长期没发现。
   已在 `SequentialTask` / `ConcurrentTask` 加守卫。
6. **PowerShell 输出习惯**：`… | Select-Object -Last 30` 会缓存全部输出直到命令结束，长任务看不到进度；
   改用 `Tee-Object -FilePath <log>` + `tail`（默认写 UTF-16）。
7. **从 Bash 调 `cmd.exe` 可能被安全策略拦**；`.bat` 用 PowerShell 直接 `& ".\xxx.bat"` 更稳。
8. **`mklink` 不适合在 Qt 里调**：`QProcess` 会按参数逐个加引号，带空格路径被转义坏；自己拼又踩另一套规则。
   **结论：不做目录联接**，资源迁移直接搬文件 + 改路径解析。
9. **AUTOUIC 按包含它的 `.cpp` 所在目录找 `.ui`**：在 `ui/pages/instance/` 里 include 一个位于
   `ui/widgets/` 的 ui 头 → 编译中止。要么把构造函数留在头里，要么 `findChild<QTabWidget*>("settingsTabs")`，
   不碰生成的 ui 头。
10. **`install_jar()` 默认装进 `Unspecified` 组件**，而 `tools/package-windows.ps1` 只装
    `Runtime` / `bundle` / `portable` —— 便携包里就少了整个 `jars/`，表现为启动器报「找不到 Java 检查库」、
    Java 检测永久转圈（[06 §99](06-变更记录.md)）。写法必须是
    `install_jar(<target> DESTINATION "${JARS_DEST_DIR}" COMPONENT Runtime)`：CMake 3.31 的这个函数只在
    **正好两个参数**时认位置式 DESTINATION，多一个 `COMPONENT` 就改走关键字解析，configure 阶段直接
    `install FILES given no DESTINATION`。

## 3. Qt / 界面

1. **`QToolBar` 里的 widget 不能用 `setVisible()` 控制显隐**：工具栏会把它从布局摘掉，之后回不去。
   必须走 `QWidgetAction::setVisible()`。
2. **`QGroupBox + QFormLayout` 搬进页签会丢拉伸约束**：先建到顶层再用 `takeAt` 搬运，行距被撑开半屏。
   内容要**直接建进目标容器**。
3. **`clearReviews()` 别把末尾的 `addStretch` 删了不补**：只剩一张卡片时会被拉满整个滚动区。
4. **横向滚动条**：卡片里的长行会撑大最小宽度。元信息单独一行，评论滚动区
   `setHorizontalScrollBarPolicy(AlwaysOff)`。
5. **`setMinimumContentsLength` 是"字符数"不是像素**：设成 4 会把「难度：不限」裁掉。
   用 `AdjustToContents` + 合理的最小像素宽。
6. **颜色不要写死**：深色主题下 `#2e7d32` 的对比度只有 1.6:1。统一走 `MapTheme.h` 的
   `confidenceColor / starColor / mutedTextColor / cardStyle`；尺度走 `MapStyle.h`。
7. **`customContextMenuRequested` 的坐标已经是视口坐标**：再 `mapFrom` 一次会整体上移一个表头（32px），
   表现为"右键 A 行、弹出 B 行菜单"。`QPoint` 不带单位，映射错了不报错，只静默错位。

## 4. Minecraft / Agent

1. **`World::repath()` 只在 `suffix()=="zip"` 时走 zip 分支** —— 识别层没有复用它，自带
   `LevelDatReader` + `ArchiveReader`，不碰上游代码。
2. **`MMCZip::ArchiveReader::parse()` 的回调里 `true` 表示"停止"**（`shouldStop`）。写 `return true;`
   只处理第一个条目就退出 —— 扫描资源包时因此漏掉 `level.dat`，把"既有 `pack.mcmeta` 又有世界"的包
   误判成资源包，导入时建出空世界。扫描回调一律 `return false;`。
3. **Forge 会把 `System.out` 重定向进 log4j**：Agent 事件从那一刻起收不到，必须**自己写日志文件**，
   宿主轮询 `agent.log`。参数还要落**系统属性**，防止 LaunchClassLoader 加载出第二份副本读到空配置。
4. **主菜单出现 ≠ 存档落盘**：退出判定必须等 `saveAllWorlds` 的 RETURN 点，且是退出请求之后的保存；
   否则丢一个自动保存周期。`haltOnSafe=1` 让 JVM 自己退比宿主 kill 可靠。
5. **Forge 1.12 的退出拦截**：`TerminalTransformer` 把非 Forge 类的 `halt/exit` 重写，
   `FMLSecurityManager` 抛 `ExitTrappedException`。三条一起做才闭环：Agent 类转换期在
   `LaunchClassLoader` 注册 `addTransformerExclusion("mcml.agent.")`；`terminateJvm()` 优先调
   `FMLCommonHandler.instance().exitJava(status, abortive)`；外层 `MapQuitWatcher` 监听 `EXIT_SAFE`
   并在 700ms 未退时兜底。
6. **1.20+ 的「退出存档后关游戏」只能读日志**：这条轨道没有 Agent，拿不到"落盘完成"回调。
   可靠信号是两行英文日志：`Stopping singleplayer server as player logged out` 与
   `All dimensions are saved`。看到后者再发 `WM_CLOSE`；等不到就 10 秒兜底。
7. **关游戏用 `WM_CLOSE`，不用 TerminateProcess**：等同玩家点 ×，走游戏自己的退出流程；
   8 秒还不退才回退 `Application::kill()`。
8. **`runningStatusChanged(true)` 比 `getLaunchTask()` 就绪更早**：`LaunchTask::create()` 里 `init()` 先
   `setRunning(true)` 发信号，之后 `LaunchController` 才把对象写进 `m_launchProcess`。信号到达时取到的
   还是**上一次**那个已结束的任务（第一次是 `nullptr`，重试能躲过去，第二次就静默连到死对象）。
   凡"拿到任务再挂日志/信号"的逻辑都不能只靠这个信号，要么定时核对指针，要么等真正的 `start()`。
9. **quickPlay 进图时窗口没焦点 → 鼠标抓不住**（Mojira **MCL-24083**，重复上报 MC-271193 / MC-274999）。
   MC 在 `screen == null` 那一帧 `grabMouse()`，失败后自己的 `mouseGrabbed` 已是 true，**不会再重试**；
   它只靠"收到过失焦事件"决定要不要暂停，所以从创建起就没焦点时既不暂停也不抓光标。
   玩家自救是按 Windows 键或开关一次暂停菜单；启动器兜底是 `MapWindowFocus`（只在本进程仍占前台或
   没有前台时动手，绝不从别的程序抢）。
   **这条不是"视角乱转"的元凶**，见下一条。
10. **「视角顶死 / 轻微一动就狂转」先查远程控制软件**（ToDesk / 向日葵）。它们的虚拟显示器与输入注入
    会让 MC 每帧读到的鼠标增量变成大常数。2026-11-03 排查三轮，**断开远控即恢复**。
    排查顺序固定：① 断开/退出远控 → ② 用官方启动器跑同一个原版实例 → ③ 才怀疑启动器。
    「关掉远控窗口」不等于「断开远控」：`Get-Service ToDesk_Service`、`Get-CimInstance Win32_VideoController`
    能看到驱动是否还挂着。
11. **OptiFine 的列表和 jar 不是一条路**：列表走 BMCLAPI（`/optifine/<mc>`，滤掉 `preview_*`）；
    下载时 BMCLAPI 会 302 到一个直连被 reset 的域名，官网 `adloadx → downloadx` 带 `Referer` 能取到真 jar。
    顺序是 **BMCLAPI（90s，2 次）→ 官网（2 次）**。
12. **旧 `map.json` 的 `requiresExternalModpack` 是误判产物**：`ServerBrands` / `WasModded` 只说明作者
    自己开了模组。判据改成只看 Forge 写在 `level.dat` 里的 `FML LoadingModList`；`MapMeta::load` 对旧文件钳位。
13. **启动组件检查必须「本地离线优先」**：上游把在线模式直接映射成 `Net::Mode::Online`，而索引文件没有
    父级校验哈希，于是每次启动都向境外拉 `index.json` —— 境内网络下会卡在「已收 0.00 KiB」数分钟。
    已装且版本固定的实例强制以 `Offline` 校验本地 `meta/` 缓存，0 请求 0 毫秒。
14. **Java Agent 的 ASM 版本决定它能改哪些版本**：`quickboot.jar` 曾内嵌 ASM 5.2（只到 Java 8），
    遇到 1.17+ 的 class（major 61）直接 `IllegalArgumentException`，表现是 `transform failed` + 停主菜单。
    换 ASM 9.7.1 还不够 —— visitor 的 api 必须一起抬到 `Opcodes.ASM9`，否则抛
    `UnsupportedOperationException: NestMember requires ASM7`。
15. **托管运行时的版本别按目录名猜**：`java-runtime-gamma` 是 17、`delta` / `epsilon` 是 21，
    但快照运行时与第三方塞进来的目录不受这套命名约束。可靠来源是运行时根目录里的 `release`
    文件（`JAVA_VERSION="17.0.8"` / `OS_ARCH="x86_64"`）；读不到才退回目录名对照表，
    两边都判不出就**不列进候选**（宁可显示"没找到"）。

## 5. 已定决策

### 5.1 产品边界

| 决策 | 理由 |
| --- | --- |
| **不嵌 Node 跑 AIO 的 `launcher/src`** | 双运行时 + 双错误边界 + 打包体积；AIO 的判断逻辑是纯函数，C++ 重写才划算 |
| **不复活"一个高版本核心通吃"** | 1.13 / 1.16–1.20 / 1.20.5 三次语义断裂，DFU 不翻译命令方块 |
| **下载一律交系统浏览器** | 分享页的 Cloudflare 只认可见浏览器，AIO 试过七种"藏窗口"全失败 |
| **不做自更新、不订阅上游新闻** | 更新器指向上游仓库，装上等于把自己覆盖成 Prism；RSS 标题不属于本启动器 |
| **不做启动器内的地图机器翻译** | 2026-11-15 整体移除：效果不达标而占地大。需要时 git 里的 15 个文件比一个 `if` 更好找 |
| **符号表离线生成、运行时只读** | 实时解析要扫 jar，秒级开销；AIO 已算好，直接当静态资源 |
| **不把符号解析器重写到 C++** | 工作量 ×3，收益为零 |
| **实例目录名沿用 Prism 的"名称派生"** | 改 `InstanceStaging` 会波及列表/快捷方式；AIO v0.28 改 UUID 又回滚了 |
| **世界目录固定 `MapWorld`** | quickPlay 与 Agent 都吃字符串；老版本对中文路径有坑 |
| **UI 融入原生，不另起模式** | 双模式 `QStackedWidget` 已按用户要求移除；地图信息区插进原生操作栏，`m_mainWindow` 的引用零改动 |
| **地图/资源设置并进设置页** | 一半设置本来就是启动器级的；两份 UI 必然漂移 |
| **双轨导入必须在入口层隔离，选择权交玩家** | 压缩包内容千差万别；私自单向拦截会误建实例。拖拽入口与导入页都要覆盖，并给双向建议 |
| **轻量 API 失败必须静默** | 搜索/分类/版本列表这类"锦上添花"的请求，网络不可达时反复重试再弹模态框会把用户挡在门口。统一 `askRetry=false` + `maxTries=1` |
| **单元测试不得走提权路径** | 符号链接建不出来就 `QSKIP`；之前每个用例都 `runPrivileged()`，一次全套弹 14 次 UAC |

### 5.2 数据模型与身份

| 决策 | 理由 |
| --- | --- |
| **`map.json` 独立于 `instance.cfg`，`notes.json` 再独立一层** | INI 表达不了数组与证据链；"这张图是什么"（自动）与"我怎么看这张图"（人写）必须分开存 |
| **`map.json` 不重复 Prism 已有字段** | 版本在 `mmc-pack.json`、名称在 `instance.cfg`；重复就会漂移 |
| **图的身份锚在 CTM 大厅 slug，不锚文件名** | 文件名会改会重名；slug 是站上主键。改名/换盘/换机器都不会拆成两组，没关联时才退回归一化图名 |
| **一张图的两种载体必须分开记：整包 vs 资源包** | 资源包没有世界，建实例会得到空世界；所以 `variant.delivery` 是模型的一部分 |
| **变体的语言判定只认文件名，不认备注** | 备注里会写"与繁中版同图不同语言"，拿它当证据会把英文原版判成繁中（`Ragecraft III` 实测） |
| **实例记住自己属于哪个语言版本（`map.json.variant`）** | 光靠 `libraryCopy` 只知道"用哪个包"，不知道"这是原版还是汉化"；重装对话框因此能列出同组全部版本 |
| **显示名单独存 `title`，不进分组键** | 分类/身份都挂在名字上时，"改名"和"别拆组"是冲突的：没关联大厅时分组键退到 `englishName`（再空则 `chineseName`），直接改中文名会把同组的语言版本拆开。`title` 只影响显示，改名永远安全 |
| **自动匹配只作建议，写进索引必须人工确认** | 6 组语言变体里字符串相等只配上 2 组；关联错了比不关联更糟。匹配器给候选 + 理由，只在"一枝独秀"时预选 |
| **`metacache` 只能合并、不能覆盖** | 它是"哪些库文件算已下载"的账本；用旧备份盖掉新账本会让已下好的文件被判未下载而重下 |
| **账本缺失 ≠ 文件缺失：已有库文件按 sha1 认领** | 账本在数据目录、文件在共享目录，换机器时天然对不上。只认内容不认文件名，恰好挡住"同名但截断" |
| **资源目录用真路径，不用 junction** | 备份/换机器/给别的启动器复用没有隐性依赖；改完立即生效（基址一起换），只有手改 `atlas.cfg` 才要重启 |

### 5.3 启动与退出

| 决策 | 理由 |
| --- | --- |
| **启动准备挂在 `Application::launch`，不挂在主窗口** | 启动入口有五个，漏一个就会让老版本静默停在主菜单 |
| **轨道只认 trait；traits 为空时用版本表兜底** | 写死 `>=1.20` 会在 Forge/NeoForge 派生版本上出错；冷启动组件未解析时 `traits()` 为空，不兜底会把 1.20+ 推进 Agent 分支 |
| **`-javaagent` 走运行时属性，不写 `JvmArgs`** | `JvmArgs` 是 override 设置：`OverrideJavaArgs=false` 时实例里写的值**永远读不到**，quickboot 曾因此静默失效 |
| **Agent 用 `haltOnSafe=1`（JVM 自己退）** | Prism 侧没有"落盘完成"概念，宿主 kill 时机靠猜 |
| **Agent 退出停机接 Forge 官方白名单** | Forge 1.7.10–1.12.2 严防非 Forge 类调 `halt/exit`；`FMLCommonHandler.exitJava` 是规范且豁免的路径 |
| **`MapQuitWatcher` 用 `EXIT_SAFE` 做外部守护** | 模组环境千奇百怪；启动器看到 `EXIT_SAFE` 后 700ms 兜底关窗，形成双保险且杜绝坏档 |
| **启动后把前台交给游戏窗口** | quickPlay 无焦点抓不住鼠标（MCL-24083）；只在本进程占前台或没有前台时动手 |
| **「实验性设置」确认页用运行时补丁跳过，绝不动世界数据** | 改 `DataPacks.Enabled` 会让已生成区块失去引用（坏档）；改 `pack_format` 也没用，判定依据是包内容 |
| **1.19+ 进图走 `WorldOpenFlows.loadLevel`，不给 `doWorldLoad` 装配参数** | 后者的 storage access 要先开文件锁，装错就是坏档风险；`loadLevel` 是「选中存档 → 进入」按钮自己走的路 |
| **Agent 的 ASM 与 visitor api 一起升级** | 类文件版本上限由 ASM 决定；只换 jar 不抬 api 会卡在 `NestMember requires ASM7` |
| **Agent / Java 侧日志路径必须纯 ASCII** | 中文 Windows 的 `sun.jnu.encoding=GBK`，实例名里的 `Ξ` 会让 `FileWriter` 抛"找不到路径"，日志静默丢失 |
| **`options.txt` 的语言与键位按 1.13 分代写，判不出代就一条都不写** | 两代写法互不兼容：1.8 读到 `key.keyboard.*` 会把蹲/跑**静默回默认**，比不写更糟 |
| **写 `options.txt` 的每一项都要能回答"这个版本有没有这个键"** | 写错键不会坏档（游戏打一行 `Skipping bad option`），但玩家会以为"勾了没生效"。所以 `autoJump` 只在 1.8+、`clouds`/`renderClouds` 按键名分代、V=47 不是 F5 的 63 |
| **`renderClouds` 的引号跟着文件走，不跟版本猜** | 1.19 起游戏自己写 `"false"`，更早写裸 `false`。文件里已有这一行就沿用它的方言 |
| **「导入时的游戏设置」只在导入对话框里选，勾过的记住** | 设置页那组开关是替未来某次导入做决定，玩家点「导入」时看不到会写什么 |
| **Java 只在 `compatibleJavaMajors` 里挑，缺了就报「没有」** | "高一点大概也能跑"是最容易把模组/存档弄崩的做法（1.12 Forge 跑 Java 17 直接崩）；宁可让玩家去装 |
| **自动改写 Java 只发生在「没手选过」的实例上** | 玩家手选过就是意图。判据是 `OverrideJavaLocation && !AutomaticJava`；手改路径会清掉 `AutomaticJava`，自动写入会置回 `true` |
| **选推荐项仍归自动流程管，选其它才算手选** | 否则点一次「使用推荐」就把实例从自动流程里摘出去，以后版本变了还得再点一次 |
| **MC 版本 → Java 主版本以 meta 为准，版本表只做兜底** | 整合包/加载器会在 meta 里叠加自己的约束；版本表只覆盖"刚建实例、meta 还没解析"的那一小段窗口 |
| **「跳过确认页」与「自动进图」互不依赖** | 曾经 Plain 轨道一个 agent 都不注入，于是关掉自动进图就把确认页也带回来了；现在三条轨道都注入，两个开关各自判断 |
| **「退出即关」只看 `closeOnQuit`，不看 `autoEnter`** | 写成 `autoEnter && closeOnQuit` 时，玩家从主菜单手动进图的实例退出后不关窗（2026-11-19 实测） |
| **Fabric 下按 intermediary 映射 + 描述符形状匹配** | 混淆名表在模组环境根本不存在（`ftm` 变成 `class_7196`）；形状匹配对版本漂移也更宽容，代价是必须要求唯一命中 |

### 5.4 下载与换源

| 决策 | 理由 |
| --- | --- |
| **下载源只在 HTTP 层改写一次、映射表之外不猜** | 改在 `Net::Request::executeTask()` 一处覆盖资源/库/版本 json/运行时清单；302 目标不在表里所以不会二次改写。Modrinth / CurseForge 是数据接口，**永不映射** |
| **镜像请求直连，不继承启动器代理** | BMCLAPI 会 302 到各 OpenBMCLAPI 节点，代理会把这些跳转掐掉（实测） |
| **镜像节点抖动靠重试，不做节点池** | 单次成功率仅 30–50%（302 到随机节点）；节点池等于自己维护一份镜像拓扑 |
| **重试必须回到镜像入口，不是失败的那个节点** | 302 之后 `m_url` 已是节点域名，继续打同一节点等于确定性失败 |
| **`FileSink` 重入 `init()` 是"截断重写"，可以放心重试** | `QSaveFile` 先写临时文件、`commit()` 才改名，半截数据不会 append 也不会毁掉原文件 |
| **传输超时（`OperationCanceledError`）不是"用户取消"** | `RequestTimeout` 到期时 Qt abort 掉 reply，报的和用户点中止一样；用户取消走 `Request::abort()`，进不到错误处理 |
| **文件下载走 HTTP/1.1，JSON/API 仍用 h2** | 一条 h2 连接跑 6 个大文件会互相饿死（实测一条流 75 秒完成、另一条 60 秒零字节）；h1.1 每文件一条连接，6 并发总吞吐一致 |
| **镜像彻底失败后回落官方一次，且只单向** | 用户选镜像是为了快；官方失败不反向切镜像（那条路上更可能下不下来）。判定写成纯函数 `shouldFallBackToOfficial()` 并单测 |
| **下载走 QNAM 池，不是提高并发数** | 一个 QNAM 每主机固定 6 条连接，并发调到 64 也只是排队；8 个 QNAM 才真的开出 48 条（实测 209 → 467 KB/s） |
| **连接池只给文件下载** | 池是轮转的，把接口请求扔进去等于把会话/cookie 拆到几个罐子里 |
| **大文件分段：先丢原连接，再发 N 条 Range** | 决定拆段时那条无 Range 的响应会把整个文件拉回来，写进第 0 段覆盖别的分片；段数不超过字节数（否则 416） |
| **分段写入必须在 finalize 时重算校验** | 分片乱序写盘，校验器拿不到连续字节流；按顺序读一遍喂给它，不通过不 rename |
| **分片的重试只能有一个入口** | `errorOccurred` 后必然跟 `finished`；两处都调重试等于一次失败花两次预算 |
| **分片失败从断点续，不整片重下** | 弱网下一片几 MB，断了从头来等于白干 |
| **绝不在 reply 自己的信号里析构它** | 曾在 `metaDataChanged` 槽里 `reset()`：QNAM 之后所有请求静默挂死。必须 `release()` + `abort()` + `deleteLater()` |
| **拆段阈值 4 MB，不是 1 MB** | 1 MB 的库拆 8 段是负收益：请求数 ×8、TLS 握手 ×8，对端连接数打到 190+ |
| **死连接要有独立闸门** | 服务器不回包也不断开时，Qt 的传输超时只在 `RequestTimeout`（默认 60 秒）后触发；建好 reply 就起 20 秒表，**收到响应头后不停表，而是重新起表** |
| **换源回落必须双向且互斥** | 只有"镜像→官方"时，选了官方又遇 stall 就毫无退路；两方向各一次且互斥才不会绕圈 |
| **"慢"和"卡死"要分开判** | 传输超时只认完全没数据；20 KB/s 的界面看起来一样死。按 10 秒窗口统计吞吐，连续两次低于 15 KB/s 换连接 |
| **空闲看门狗必须覆盖整条传输** | "收到 200 之后 body 再也不来"最常见：Qt 在这种情况下不一定触发超时，实测一个请求挂了 3542 秒 |
| **分片的"慢"在片这一级判，并保留断点** | 分片模式曾完全绕过吞吐看门狗；慢片 abort 后走 `retryChunk` 从断点续，换两次还慢就放行 |
| **顺序下载写 `<目标>.part`，不用 QSaveFile 的隐藏临时文件** | 只有"看得见、留得住"的临时文件才能续传；`QSaveFile` 的临时文件在 `abort()` 时就没了 |
| **续传必须把已有字节补喂校验器** | 校验器是流式哈希，只喂新数据算出来必然不对 |
| **服务器无视 Range 就 `restartFromZero()`** | 带了 Range 却收到 200 意味着"整份内容"，继续 append 会得到内容 ×2 |
| **分片 scratch 用 `.part.parallel`，与断点文件分离** | 分片是"预分配 + 空洞"，顺序断点是"从 0 开始的连续前缀"；混用会把空洞当数据 |
| **分片失败先减半段数再退单连接** | `libraries` 会随机关并发连接；现在 `max(4, n/2)` 再试一次，仍失败才单连接 |
| **单片连续 3 次零进展不算"越界"，先减半段数** | 某些主机对某一段持续不理人，硬试 6 次 = 6 分钟白等；阈值从 2 提到 3 是因为 `libraries` 会随机关连接 |
| **文件下载强制走 QNAM 池，忽略 NetJob 塞进来的主 QNAM** | `NetJob::addNetAction()` 会给每个请求 setNetwork(主 QNAM)，只要"为空才挑池"，池就永远用不上 |
| **同一个目标文件同时只允许一个 sink 用 `.part`** | 两个组件并行拉同一个 `meta/index.json` 会互相覆盖；416 之后删不掉（被对方打开）→ 越界 → 重试 → 还是越界 |
| **下载观测做成旁路** | `NetJob` 只在构造/析构登记，界面 500ms 轮询；删掉界面不影响网络层 |
| **下载总速度必须从活跃个体增量累加，不可用总量相减** | 活跃文件完成移出快照会让总量骤降十几 MB，差值出现巨额负数打崩平滑值 |
| **`FileSink` 异常退出时必须即时释放 part 占用** | 否则后续请求误判冲突并多退一步 |
| **classpath 里的库路径必须与库文件实际目录同源** | 相对 `"libraries/"` 按进程工作目录解析，设了共享目录后 `-cp` 全是旧目录 → 客户端 `ClassNotFoundException` |
| **换资源目录必须同步 metacache 基址，且条目里的绝对路径要一起改** | 基址只在启动时注册一次；不同步会按旧根解析 → 文件已搬走 → 条目被除名并写盘 → 重启后整份重下（真机 2.1 GB） |
| **素材索引按内容复用，不按时间刷新** | 版本 json 的 `assetIndex.sha1` + 大小就是上游对这份清单的承诺：一致就跳过（1.21.1 每次启动省 450 KB），不一致说明本地缺或**上游重发过索引**，必须重下。用它当"索引变了"的探测器，比定时刷新准 |
| **孤儿素材暂不清理** | 本机 1,788 个 / 1.06 GB 没有任何索引引用（多数是历史语言包，如 1.21.1 换索引后留下的 142 个）。要清理只能是资源页里的显式按钮 + 默认不勾选：一旦上游把索引换回旧版、或玩家回滚到旧版本，这些是唯一副本 |

### 5.5 大厅与网络通道

| 决策 | 理由 |
| --- | --- |
| **被封 SNI 的站一律借本机浏览器**，不在 C++ 里实现 ECH/QUIC | Qt 在 Windows 走 Schannel，没有 ECH；自己实现等于重写 TLS 栈 |
| **大厅整库本地化，点开只读本地** | 每个请求都要借浏览器，现拉一次十几秒；本地化后搜索/详情/评论是毫秒级 |
| **大厅整库同步必须按 offset 翻页** | PostgREST 单次上限 1000 行：`limit=1000` 一个请求把 2287 张静默截成 1000 张，后一半在搜索与匹配里完全不存在 |
| **错误页只回答三个问题：发生了什么 / 为什么 / 现在能做什么** | 取证过程折进「技术细节」；同一原因不在状态栏再抄一遍；失败时右栏整块收起 |
| **不做启动器内下载** | 同上：Cloudflare 只认可见浏览器 |

### 5.6 界面与工程纪律

| 决策 | 理由 |
| --- | --- |
| **默认行为一个字节都不能变** | 换源、预设、离线优先都做成"开关 + 默认关/等价旧行为" |
| **显示名必须能区分变体，且不许重复** | 否则「Bitstream - by …」连写三行，玩家只能靠右边小字猜哪行是汉化 |
| **同一类别的标签必须同字数** | `简中` 与 `简中汉化v1.0` 并列时看不出是同一类东西；括号原话进 tooltip。允许变长的只有「资源包」后缀 |
| **列表层级只靠字重与缩进，不靠颜色** | 一排灰字里有两条粗体，眼睛就知道那是"几张图"而不是"几个包" |
| **子行只写「地图版本 + 语言」，并压到半高（16px）** | 子行回答的是"这张图的哪个版本"；四列重复会让人以为每行都是一张图。空列也要放空 item，否则选中底色断成两截 |
| **多版本组默认收起，折叠标记用图标不用字符** | 摊开后"我拥有几张图"看不出来；`▸` 配空格补齐会随字体差一两个像素 |
| **组标题写 MC 版本、不写地图版本** | 一组可能有好几个地图版本，写哪个都偏心；"这张图跑在什么版本上"才是扫列表时最想知道的 |
| **组菜单不给"导入默认版本"** | "默认"是程序挑的，玩家要自己挑；与"导入特定版本"并存还会被当成推荐，点错就多建一个实例 |
| **地图库右键分三级，互不越权** | 组标题=整组操作；子行=只能改自己的字段；独立图=两者合一。子行改类别会让整组立刻变「混合」，所以不给 |
| **实例名里的系列标签要翻译成站上的系列名** | `RC3` 对不熟的人等于没写；表里没有的代码**原样显示** —— 猜一个系列名会把两张不同的图叫成同一系列 |
| **标签统一灰色、比名字小两档，且放在名字下方** | 按系列上色会让一排彩色小字压过图标；标签是脚注不是主体。放不下用 `elidedText` |
| **分类栏用 `ALL` + 正字面等宽 + 整数号** | 「全部」两个汉字永远比下面的英文名宽；系统 `FixedFont` 在 Windows 常落到 Courier New，8.5pt 会被 DirectWave 缩放采样 —— 这才是"糊"的来源 |
| **列表列宽存 `MapLibraryColumnState`，400ms 防抖 + 析构兜底** | 拖动时 `sectionResized` 连发几十次；只靠定时器，拖完立刻关窗口会丢那 400ms |
| **导入页不留「先看摘要、再点导入」这一步** | 选完文件就等于"要导入这张图"：名称/世界/版本在对话框里都能改，放在前面只是多一次点击 |
| **地图分类采用方案 B 动态管理** | 纯英文短名根除截断；`Other` 兜底，删分类自动归并，保证数据无悬空 |
| **重装地图提供可选备份与中文「是/否」** | 解压校验成功后再处置旧存档；按钮显式中文，避免 Qt 宏英文退化 |
| **Debug 目录不放数据，用 `--dir` 指向真实便携根** | 实例 / 地图 / 大厅缓存只留一份，调试看到的就是玩家那套；Debug 会往那里写设置、日志、账本，所以**别和 Release 同时开**。`portable.txt` 留着：不带 `--dir` 时退回空目录，正好当 UI 沙箱 |
| **中文来源名一律 `QString::fromUtf8`，`QLatin1String` 只包 ASCII** | 源码里的中文是 UTF-8 字节；更隐蔽的是「压缩包名权重 ×3」也靠这个字符串比较，解码不一致会让权重静默失效 |
| **符号表必须逐槽位对着真实 client jar 校验，缺口宁可降级也不猜** | 「表里写着」和「jar 里有」是两件事：原 1.7.10 表的 `blr/bib` 是 1.12.2 的名字 |
