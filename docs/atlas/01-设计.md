# 01 · 设计与架构

> 目标：在**不改 Prism 既有语义**的前提下，把"地图"变成一等公民 —— 点一张地图卡片，直接落在它的出生点。
> 原则：**新代码只放新目录；对既有文件只做加法**（改签名 = 未来每次 rebase 都要打一次架）。

本文只写"为什么这样设计、东西放在哪"。现在到哪一步看 [04](04-进度与待办.md)，验证到哪一档看
[05](05-验证记录.md)，哪些决定不许推翻看 [03](03-决策与坑.md)。

---

## 1. 三条硬约束

传统启动器的组织中心是**版本 / 整合包**；Atlas 换成**地图存档**。这个反转把"版本"从用户选择变成
程序推断，而推断错了会毁存档 —— 所以工程重心不在 UI，在「版本判定 + 不可逆操作的闸门」。

| 约束 | 含义 | 架构后果 |
| --- | --- | --- |
| **C1 不坏档** | 绝不用高于地图原生版本的客户端打开存档（DFU 升档单向不可逆） | 判定必须带置信度与证据；判不出就拒绝；实例物理隔离 |
| **C2 机制还原** | CTM/RPG 依赖命令方块时序、红石更新顺序、怪物 AI | 必须跑在地图原生版本的集成服务端上，不能协议层翻译 |
| **C3 空间与等待可控** | 20 张图不能占 20 GB；点地图不能等 20 秒 | 共享资源池 + 每实例一份 `--gameDir` |

C1 是红线，冲突时优先保 C1；C3 可以妥协。

**为什么不能"一个高版本核心通吃"**：1.13 扁平化、1.16–1.20 数据包、1.20.5 物品组件化三次语义断裂；
DFU 只升区块，**不翻译命令方块**。这条路线被永久否掉。

**空间账**（一个"版本"其实是四层解耦结构）：

| 层 | 体积 | 复用性 |
| --- | --- | --- |
| 版本核心 jar + json | 5–30 MB | 不可复用，真正的差异化文件 |
| `libraries/` | 200–500 MB | 高度复用 |
| `assets/` | 600 MB–1 GB | 完全复用（SHA-1 内容寻址） |
| Java 运行时 | 150–300 MB/代 | 按代际复用 |

所以不是发明共享机制，而是**每实例一份 `--gameDir`，所有实例共享同一份 assets / libraries / java**，
空间从 O(版本数 × 全量) 降到 O(版本数 × 20 MB)。

## 2. 与 Prism 的关系

结论：Prism 已经有"半张地图启动器"，甚至 `--quickPlaySingleplayer` 与 `-javaagent` 通道都是现成的。

### 2.1 直接复用（不改代码）

| 能力 | Prism 里的实现 | 用途 |
| --- | --- | --- |
| 从 zip 读世界 + 定向解压 | `World::readFromZip()` 扫条目找 `level.dat`；`World::install()` 走 `MMCZip::extractSubDir` | 嗅探与"只解一棵子树" |
| 归档格式 | `archive/ArchiveReader`（libarchive：zip / 7z / rar / tar / gz） | 三种压缩包统一入口 |
| NBT | `libnbtplusplus`；`World::loadFromLevelDat` 已解析名字/时间/模式/种子 | 只缺 `Data.Version.*` 与 `DataVersion` |
| 版本核心 + 依赖 + 资源 | `PackProfile` / `AssetUpdateTask` / `DownloadTask` | 环境补齐 |
| Java 托管 | `AutoInstallJava` + `Launcher_ENABLE_JAVA_DOWNLOADER` | 按大版本自动装 |
| 实例生命周期 | `InstanceTask` / `InstanceStaging` / `VanillaInstanceCreationTask` | staging → 提交，失败自动清理 |
| 直连存档 | `MinecraftTarget::world` + `JoinWorldOnLaunch` → `--quickPlaySingleplayer` | 轨道 A |
| `-javaagent` | `VersionFile::agents` + `LaunchProfile::applyAgent`；实例运行时属性 | Agent 注入通道 |
| 模组 / 加载器 / 实例网格 / 主题 / i18n / 打包 | 现成 | 不重写 |

### 2.2 Prism 没有的（本项目的增量）

| 缺口 | 为什么没有 | 做法 |
| --- | --- | --- |
| 三级版本判定 + 置信度 + 证据链 | Prism 只把 `level.dat` 当元数据显示 | 见 §7.1 |
| 地图归档完整嗅探 | `World` 只找第一个 `level.dat`，不认材质包/随包模组/README | `MapArchiveScanner` 单趟扫全包 |
| 导入即建实例的编排 | `InstanceImportTask` 是整合包语义（读 `mmc-pack.json` / manifest） | `MapImportTask`（继承 `InstanceTask`） |
| ≤1.19.4 直连 | 低版本没有 quickPlay trait，`world` 会被静默忽略 | Java Agent + 符号表 |
| 安全退出判定 | Prism 只有"进程退出"，没有"存档已落盘" | Agent 判定 + 日志看门狗 |
| 地图大厅 / 本地地图库 | 无 | §9、§10 |

### 2.3 关键差异（直接影响实现）

| 主题 | 结论 |
| --- | --- |
| 实例目录名 | 沿用 Prism 的"名称派生"（`FS::DirNameFromString`）；不为 UUID 改 `InstanceStaging` |
| 元数据 | 新增 `map.json` 只放"地图特有"的；版本在 `mmc-pack.json`、显示名在 `instance.cfg`，不重复 |
| 版本名归一化 | 存档里的 `Version.Name` 必须映射到 meta 组件 id（`1.16.5` ≠ `1.16.5-forge-36.2.39`），命中不了就降置信度 |
| 世界目录名 | 固定 `MapWorld`：quickPlay 与 Agent 都吃目录名字符串，老版本对中文路径有历史坑 |
| 进程模型 | 单进程 + `LaunchTask` 步骤链：事件流从"解析子进程 stdout"变成"解析启动器日志行" |
| UI | QWidget；布局概念可平移，CSS 语义令牌换成 palette + `MapTheme` / `MapStyle` |

## 3. 路线选择

| 路线 | 结论 | 理由 |
| --- | --- | --- |
| **同一二进制，地图融入原生界面** | **采用** | 复用实例网格/账号/Java/更新/翻译；地图卡片插进原生实例操作栏，`Application::m_mainWindow` 的引用零改动 |
| 独立地图模式主窗口（双模式 `QStackedWidget`） | 曾经规划，**用户否掉** | 两个主窗口 = 两套状态与入口，地图实例在原生网格里反而看不见 |
| 独立 CMake target（`PrismMaps`） | 延后 | Prism 是单一可执行文件，拆分要先做 `launcher_core` 静态库，属上游级手术 |
| 另开 fork 把 `MainWindow` 改成画廊 | 否 | 丢掉实例网格，上游同步极痛 |
| 内嵌 Node 跑 AIO 的 `launcher/src` | 否 | 双运行时 + 双错误边界 + 打包体积；判断逻辑是纯函数，C++ 重写更划算。**只搬 Java Agent 与符号表**（它们本来就是 Java，只通过命令行参数和日志交互） |

## 4. 总体结构

```
              ┌──────────────────────────────────────────────┐
              │ 既有界面（只接线，不改语义）                    │
              │ 主窗口操作栏 · 实例「地图」页 · 设置页 · 导入页   │
              └───────────────────┬──────────────────────────┘
                                  │ 只发命令 / 只读结果
              ┌───────────────────▼──────────────────────────┐
              │ launcher/maps/（新增，全部业务判断在这里）       │
              │ 识别 → 导入 → 启动 → 大厅 → 界面 → 设置         │
              └───┬───────────────┬───────────────┬──────────┘
                  ▼               ▼               ▼
            Prism 既有       quickboot.jar   HallAPI / BrowserFetch
            实例/启动/下载    introskip.jar   + hall-cache.json
                  │           + 60 张符号表          │
                  └───────────────┬──────────────────┘
                                  ▼
                         ResourcePaths（assets / libraries / java）
```

唯一"跨模块"的新增是 `launcher/ResourcePaths`：资源目录要被 Prism 各处读到，放 `maps/` 里不合适（§5.4）。

## 5. 数据与磁盘

### 5.1 实例目录

```
instances/<map-id>/                 # map-id = FS::DirNameFromString(地图名)；改名不动目录
├── instance.cfg                    # Prism 既有：name / iconKey / JoinWorldOnLaunch / 内存 / Java
├── mmc-pack.json                   # Prism 既有：net.minecraft=1.16.5 (+ net.forge=…)
├── map.json                        # 地图特有元数据（§5.2）
├── notes.json                      # 玩家自己的数据（§5.3）
├── hall-link.json                  # 实例 ↔ 大厅关联（删文件即解除）
├── icon.png                        # 从存档 icon.png 提升
└── .minecraft/
    ├── saves/MapWorld/             # 定向解压，目录名固定英文
    ├── saves/MapWorld_2/           # 一包多世界时的次存档
    ├── resourcepacks/<pack>.zip
    ├── mods/*.jar
    └── options.txt                 # 合并写入，不覆盖其它键
```

### 5.2 `map.json`（自动产生，只回答"这张图从哪来、凭什么判成这个版本"）

```json
{
  "schema": 1,
  "title": "Bitstream - by Gibbs & Asometric",
  "archive": { "path": "…/原包.zip", "size": 17676422, "libraryCopy": "…/maps/[1.16.5]Bitstream….zip" },
  "version": {
    "mcVersion": "1.16.5", "confidence": "HIGH", "decidedBy": "detector",
    "evidence": ["Data.Version.Name：原始值 \"1.16.5\" → 1.16.5", "Data.Version.Id：Version.Id=2586 → 1.16.5"]
  },
  "worlds": [{ "folder": "MapWorld", "sourceRoot": "[1.16.5] Bitstream World 1.16.5" }],
  "loader": { "type": "vanilla" },
  "variant": { "kind": "original", "language": "unknown", "delivery": "archive", "source": "unknown" },
  "stats": { "playSeconds": 0, "lastExit": "unknown" },
  "importedAt": "2026-11-12T05:40:07Z"
}
```

- **不塞进 `instance.cfg`**：INI 表达不了数组与证据链；那还是 Prism 的领域（类型/默认值语义）。
- **不重复 Prism**：版本在 `mmc-pack.json`、显示名在 `instance.cfg`、启动参数也在 `instance.cfg`。
- 读写只有一个薄封装 `MapMeta::load/save`，全工程只此一处碰这个文件。
- `archive.sha1` 目前恒空：导入时不为了算哈希多读一遍大包（§4 待办里记着）。

### 5.3 `notes.json` 与库索引

| 文件 | 内容 | 纪律 |
| --- | --- | --- |
| `notes.json` | 中文名 / 评分（0–10，半星）/ 笔记（≤2000 字） | **玩家数据。任何自动流程都不许写**；重装会保留 |
| `map-library.json` | 库索引：文件名为键、分类、`hall.slug`、`variant`、地图版本、显示名 `title`、列宽 | 自动流程只写 `verified:false`；未知字段原样保留，`QSaveFile` 原子替换 |
| `hall-cache.json` | 大厅整库（列表 / 详情 / 评论 / 用户名） | 只读缓存，可删可重建 |

### 5.4 三份公共资源

| 目录 | 内容 | 默认 |
| --- | --- | --- |
| `assets` | 素材本体（`objects/` 按 sha1 平铺）与索引 | `<数据目录>/assets` |
| `libraries` | Maven 布局类库 + 每版 client jar | `<数据目录>/libraries` |
| `java` | Mojang 运行时 | `<数据目录>/java` |

设 `SharedResourceDir` 后三者改到 `<共享目录>/…`。**用真路径，不做目录联接**：迁移 = 搬文件
（同盘 rename，跨盘复制后删源）。

改完**立即生效**：`Application::refreshResourcePaths()` 会把 metacache 的 `libraries` / `asset_indexes`
基址一起换掉。边界：`meta/` 与 `metacache` 不跟着走（按数据目录解析），账本里存相对路径 + md5，
所以搬完仍然有效。历史 bug 与修法见 [03 §5](03-决策与坑.md)、[06 §70](06-变更记录.md)。

1. **不猜版本**：解析不到匹配文件就标红、取消勾选、不下载；绝不"拿个近似版本试试"；

   上限 60，天然挡住依赖环。

## 7. 两条主流程

### 7.1 导入

```
拖拽 / 库双击 / 「从外部导入…」/ 新建实例页
        │
        ├─ 拖拽 → ImportChoiceDialog（作为地图 / 作为整合包）  ← 选择权交给玩家
        ├─ 新建实例页 → 顶部单选「整合导入 / 地图存档导入」，双向提示、一键切换
        └─ 库里的行 → 直接弹 MapImportDialog（没有"先看只读摘要"这一步）
                 │
 1 MapArchiveScanner::scan     免解压单趟：worlds[] / resources[] / ignoredPaths / warnings
 2 LevelDatReader             Version.Name / DataVersion / FML / LevelName / BorderSize
 3 MapVersionDetector         三级判定 → 版本 + 置信度 + 证据；unknown 一律拒绝
 4 MapImportDialog            名称 / 世界 / 版本 / 加载器 / 关联大厅 / 语言变体 / 9 项游戏设置
 5 MapImportTask（InstanceTask）
     5.1 staging 里建实例 + mmc-pack + instance.cfg
     5.2 解 worldRoot → saves/MapWorld（先 .tmp-world，校验 level.dat 再改名）
     5.3 资源包 / 模组落位 + options.txt 合并
     5.4 map.json + icon.png + hall-link.json + 库索引
     5.5 downloadFiles()       版本核心 / 依赖 / 资源 / Java（Prism 既有）
 6 InstanceStaging 提交 → 实例列表刷新
```

**判定分级**（对齐 AIO 的 detector）：

| 级别 | 依据 | 置信度 |
| --- | --- | --- |
| L1 | `Data.Version.Name` / `Version.Id` / `DataVersion` 命中对照表 | HIGH |
| L2 | 压缩包名 / 存档目录名 / README（按来源权重） | MEDIUM |
| L3 | Anvil 容器版本（19133/19132）+ `BorderSize` / `entities` / `players` / `datapacks` 结构 | LOW |

冲突裁决顺序固定：外部旁证一致者 → `DataVersion` → 取最低；跨主次版本降 MEDIUM 强制人工确认。
**26.x 新布局且无版本号 → 直接拒绝**（判成 1.8.9 等于不可逆降级）。`unknown` 不建实例。

### 7.2 启动与退出

```
双击卡片 → Application::launch() → MapLaunchPrep::prepareForLaunch()
 ├ JavaRecommend：按 MC 版本核对 Java（只改"没有玩家手选"的实例；见 §7.5）
 ├ 有 trait feature:is_quick_play_singleplayer（≥1.20）→ JoinWorldOnLaunch=MapWorld
 │    → 启动器补 --quickPlaySingleplayer + introskip（跳过「实验性设置」页）
 └ 无 trait → 有符号表？
      ├ 有（≤1.19.4）→ 运行时属性 mapsJavaAgents 带 -javaagent → Agent 进图
      └ 无（1.17 / 1.18 / 缺表版本）→ 普通启动，停主菜单 + 顶部提示
```

轨道**只认 trait，不认版本号**（写死 `>=1.20` 会在 Forge/NeoForge 派生版本上出错）；
冷启动时 `traits()` 为空，才用 `DataVersionTable::supportsQuickPlay()` 兜底。

**退出判定**（"主菜单出现 ≠ 存档落盘"）：

| 轨道 | 信号 | 动作 |
| --- | --- | --- |
| A ≥1.20 | 游戏日志：`Stopping singleplayer server as player logged out` → `All dimensions are saved` | 发 `WM_CLOSE`；8 秒不退才强杀，10 秒等不到落盘标记也关 |
| B ≤1.19.4 | Agent 的 `agent.log`：`SAVE_DONE (quit save)` → `EXIT_SAFE` | Agent 自己 `halt`；`MapQuitWatcher` 看到 `EXIT_SAFE` 700ms 未退则代为关窗 |

Agent 轨道要求"退出请求之后的 `saveAllWorlds` 返回"才算安全 —— 周期自动保存不算。
`haltOnSafe=1` 是默认：JVM 自己退比宿主猜时机可靠。

### 7.3 Agent 契约（≤1.19.4）

参数全部由符号表生成，jar 不重编译：

```
-javaagent:<agents 目录>\quickboot.jar=world=MapWorld,menu=…,menuDesc=…,mc=…,
  launch=…,saveClass=…,saveMethod=…,saveDesc=…,stopClass=…,enterDelay=1,haltOnSafe=1,log=<实例>/agent.log
```

> **agents 目录** = `QStandardPaths::AppDataLocation/agents`，Windows 上即 `%APPDATA%\Atlas\Atlas\agents\`
> （**不在便携根里**，是"数据根 = exe 目录"的一处例外；jar 由 qrc 释放，缺了会自建，见 [04 P2 #31](04-进度与待办.md)）。
> 实测（2026-11-20，1.9.4）：`-javaagent:C:\Users\<用户>\AppData\Roaming\Atlas\Atlas\agents\quickboot.jar=…`。

- 参数的注入点是**实例运行时属性** `mapsJavaAgents`，由 `MinecraftInstance::extraArguments()` 追加；
  **不写 `JvmArgs`**（override 语义会让它在 `OverrideJavaArgs=false` 时永远读不到）。
- 事件流：`LaunchTask` 日志逐行匹配 `ENTER_WORLD_OK` / `SAVE_DONE` / `MENU_2_SEEN` / `EXIT_SAFE` /
  `EXIT_UNSAFE_TIMEOUT`。Forge 会把 stdout 重定向进 log4j，所以 Agent **同时写自己的日志文件**，
  宿主轮询 `agent.log`；参数另落系统属性，防止第二份类副本读到空配置。
- 符号表离线生成、随包只读；**每一张都要能在真实 client jar 里查到**（`tools/agent_symbol_audit.py`）。
- 60 张：59 张 Agent 覆盖 1.6.1–1.19.4，另 1 张 1.21.1 作对照。缺表版本降级停主菜单，不猜。
- 进图通道分代：1.13–1.16 走 `loadLevel(String)`；**1.19+ 走 `createWorldOpenFlows().loadLevel(null, 世界名)`**
  （游戏自己"选中存档 → 进入"那条路）；1.17 / 1.18 没有 `WorldOpenFlows`，无法自动进图。
- ASM 必须 ≥ 9（Java 17 class），且 visitor 的 api 要一起抬到 `Opcodes.ASM9`；源码在
  `tools/quickboot-agent/`。

### 7.4 introskip（跳过「实验性设置」确认页）

地图自带改过世界生成的数据包时，原版会在加载前弹一次确认页，quickPlay 就停在那里（Agent 轨道同样会停）。
它与轨道无关：表里有这个版本就注入，三条轨道都注入 —— **Plain（玩家关了自动进图）也注入**，
因为从主菜单手动进图同样会撞上这一页；1.16.5 那条还带 `defer=1`。
闸门只有一个方法 `WorldOpenFlows.askForBackup(...)`：它不加载世界，只负责弹页，玩家点
「我知道我在做什么」后执行的就是 `loadLevel`。所以补丁把**方法体整体换成 `loadLevel.run()`**，
不动 `level.dat`、不动数据包、不建备份。

`introskip.json` 现在 **25 条**（2026-11-15 补 1.19.x 与 1.16.5；2026-11-19 补 1.21.6–1.21.11），三种签名：

| 覆盖 | 描述符形态 | `loadLevel` 槽位 |
| --- | --- | --- |
| 1.16.5 | `(Screen, String, Z, Runnable)` | index 4，且 `defer:true` |
| 1.19 – 1.20.2 | `(Screen, String, Z, Runnable)` | index 4 |
| 1.20.3 – 1.21.11 | `(Screen, Z, Runnable, Runnable)` | index 3 |

类名/方法名逐版本来自 Mojang 官方 `client_mappings`（`tools/introskip-agent/gen_table.py`），
**不按名字猜**；任何一步失败只记警告、不挡启动（最坏退化成原版那样多点一次）。

覆盖边界：**1.16–1.18.2 没有 `askForBackup`**（这批版本本来也不支持自动进图，只能停主菜单）；**26.x 官方不再提供 `client_mappings`**，无法生成表项，同样按「判不出就不猜」处理。

**Fabric（以及任何把游戏 jar 重映射成 intermediary 的加载器）**：运行时类名不是 `ftm` 而是
`net/minecraft/class_7196`，方法名也变成 `method_41898`，按官方名精确匹配一定落空。现在的做法是：

1. 从 classpath 上的 `intermediary-*.jar` 读 `mappings/mappings.tiny`，把表里的**类名**翻过去
   （只查 `CLASS` 段，启动时扫一遍约 3.6 MB）；
2. 方法改用**描述符形状**匹配：把 `(Lerf$c;ZLjava/lang/Runnable;Ljava/lang/Runnable;)V` 里的每个
   `Lxxx;` 换成 `L[^;]+;`，忽略类名只看参数结构；并要求**唯一命中**，多于一个就放弃改写。

槽位（`index`）与 `defer` 仍按表来 —— 重映射只换名字，不换参数顺序。实测 1.21.1 Fabric 的
目标类为 `class_7196`、方法是唯一的 `(…ZLjava/lang/Runnable;Ljava/lang/Runnable;)V`。

### 7.5 Java 运行时（按版本自动选）

版本 → 主版本（`maps/JavaRecommend`）：

| MC 版本 | Java | 依据 |
| --- | --- | --- |
| ≤ 1.16.5 | 8 | 官方 meta；更高版本在旧 Forge / 旧字节码上会崩 |
| 1.17 | 16 | — |
| 1.18 – 1.20.4 | 17 | — |
| 1.20.5+ | 21 | 物品组件化那次语义断裂之后 |
| 26.x（26.1、26.2…） | 21 | 换了版本写法，运行环境沿用 Java 21 |
| 快照 / 认不出的写法 | **不猜** | 表里没有就什么都不做 |

判定优先用 meta 的 `compatibleJavaMajors`（加载器会叠加自己的约束），meta 尚未解析（刚建实例、冷启动）时退回版本表。
候选只取**主版本在允许集合里**的：设置里固定的路径 → meta 点名的托管运行时 → 其它托管运行时 → 已检测的本机 Java（64 位优先）→ 全局 `JavaPath`。一个都没有就报"没有符合要求的 Java"，绝不找个近似的试。

写入时机：导入建实例时一次、每次启动前一次。只改三种状态 —— 实例从没选过（`OverrideJavaLocation == false`）、上次就是自动选的（`AutomaticJava == true`）、或原路径已不存在；玩家手选且文件还在的一律不动。写入时置 `AutomaticJava=true`，所以版本换了下次能跟着换；在「Java」页手改路径会把它置回 `false`，从此归玩家。

## 8. 下载栈

七层互不替代，弱网下**串联**生效；抽掉任何一层都会退回"卡住"：

| 层 | 解决什么 | 关键参数 |
| --- | --- | --- |
| 重试 | 单次被节点掐断 / 长时间无数据 | 回到**本轮起点**（镜像 = 入口，官方 = 原地址），最多 3 次；传输超时（`OperationCanceledError`）按网络故障处理，不是"用户取消" |
| 换源回落 | 这个源本身不行 | 镜像用满 → 官方一次；官方用满 → 镜像一次；两向互斥不绕圈 |
| 空闲看门狗 | 连接彻底不动（含"有响应头、body 不来"） | 建 reply 起表，**每收到一次数据重新起表**，20 秒无字节就放弃本次尝试 |
| 吞吐看门狗 | 龟速（有数据但 ~20 KB/s） | 10 秒窗口 < 150 KB（≈15 KB/s）连续两次就换连接；单连接最多 3 次；**分片按片判**，每片 2 次 |
| 连接池 | Qt 一个 QNAM 每主机只有 6 条 HTTP/1.1 | `Application::downloadNetwork()` 8 个 QNAM 轮转（48 条）；只给文件下载，JSON/API 留在主 QNAM |
| 续传 | 一次下不完 | 顺序写 `<目标>.part`，`Range` 续，`init()` 补喂校验器 |
| 分片 | 只剩一个大文件、单连接 | ≥1 MiB 起拆，段数 = min(`DownloadChunks`, ⌈体积/512 KiB⌉)（2.56 MiB → 6 段）；写 `.part.parallel`；单片从断点续；失败先**段数减半**再退单连接；收尾重算校验才 rename |

三条不变量：

1. **官方源 URL 与行为不变**：改写只在 `Net::Request::executeTask()` 发生一次，默认 `official` 时零改动；
2. **失败不能毁掉目标位置的原文件**：两种模式都先写临时文件，校验通过才 rename；
3. **失败原因要能读懂**：不把 `Operation canceled` 原样甩给用户。

映射表之外不猜：Modrinth / CurseForge / GitHub / 地图站 API 永不映射；镜像请求走 `NoProxy` 直连
（BMCLAPI 的 302 会被启动器代理掐掉）。

镜像映射（`net/DownloadSource`，默认 `official` = 一个字节都不改）：

| 官方 | 镜像 `https://bmclapi2.bangbang93.com` |
| --- | --- |
| `resources.download.minecraft.net/<xx>/<hash>` | `/assets/<xx>/<hash>` |
| `libraries.minecraft.net/<path>` | `/maven/<path>` |
| `maven.fabricmc.net` / `files.minecraftforge.net/maven` / `maven.neoforged.net/releases` / `maven.quiltmc.org` | `/maven/<path>` |
| `meta.fabricmc.net/<path>` | `/fabric-meta/<path>` |
| `launchermeta` / `launcher` / `piston-meta` / `piston-data` | 路径原样拼到镜像根 |

同一个域下不归镜像管的路径（如 Forge 的 `promotions_slim.json`）原样返回。设置 → API 顶部的
「下载源」旁边有「测试连通性…」，用**尚未保存**的选择逐条请求四个真实文件并显示实际打到的地址。

> 观测是旁路：`DownloadMonitor` 只在 `NetJob` 构造/析构登记，界面 500ms 轮询快照，删掉界面不影响网络层。

## 9. 大厅与浏览器通道

`*.supabase.co` 在部分线路被封的是 **SNI 字符串**（DNS 正常、换端口也 reset、同 IP 换 SNI 就 200）。
Qt 在 Windows 走 Schannel，没有 ECH；Chromium 有。所以产品给四条路：

1. **浏览器通道（默认）**：本机 Edge/Chrome 无头模式打开自建临时页面，页内 XHR + 退避重试取数据；
2. 代理（`HallProxy`：环境变量 → 本地端口扫描 → 系统代理 → 直连）；
3. 反代模板（Cloudflare Workers）；
4. 离线：打开原站挑、下载完再导入。

**整库本地化**：四类接口（列表 / 详情 / 评论 / 用户名）拉到 `<数据目录>/maps/hall-cache.json`，
之后搜索、排序、详情、评论全本地算（毫秒级）。PostgREST 单次上限 1000 行，**列表与详情都按 offset
翻页**（2287 张 → 各 3 页）；少翻一页会让后一半图在搜索与匹配里静默消失。

查询用 `select=*`，**不写死列名**（站方改列是常态，AIO 为此吃过 400）；endpoint 可配置
（`MapHallEndpoint`），默认 CTM Maps 的 Supabase 基地址；anon key 是站点前端自带的公开值（受 RLS 约束
只读），随资源发布。

失败必须分三类报，处置完全不同：**空 stdout（浏览器没干活）→ 换另一个浏览器**；
**`<pre>` 还是 `pending`（页面没跑完）→ 加大预算重试**；**有 DOM 没结果节点（页面结构变了）→ 报 DOM 字节数**。
失败页只回答三个问题：发生了什么 / 一句话性质 / 现在能做什么（三条动词开头的建议），
取证收进「技术细节」。不做启动器内下载：下载一律交系统浏览器（Cloudflare 只认可见浏览器）。

## 10. 地图库模型

**一个包 ≠ 一张图。** 同一张图常有英文原版、简中、繁中三个包；玩家要的是"这张图玩哪个语言"。

| 层 | 是什么 | 键 |
| --- | --- | --- |
| **图（group）** | 一张地图的身份 | `hall.slug`；未关联时退回归一化图名（`local:`） |
| **变体（variant）** | 这个包的语言 / 载体 / 来源 | 每条目的 `variant` |

- `variant.kind`：`original` / `localized`；`language`：`en` / `zh_cn` / `zh_tw` / `other` / `unknown`；
  `delivery`：`archive` / `resourcepack`；`source`：`author` / `community` / `self` / `unknown`。
- **两种载体两条链路**：整包（有存档）建实例；资源包（只有 `pack.mcmeta`、没有 `level.dat`）
  **绝不建实例**（建出来是空世界），只能由 `MapPackAttach` 挂到已装实例的 `resourcepacks/`
  并往 `options.txt` 追加 `file/<包>`。
- **身份锚在 slug，不锚文件名**：改名 / 换盘 / 换机器都不会把同一张图拆成两组；索引以文件名为键，
  库整体搬走仍有效。
- 自动匹配只作建议：`HallMatcher` 给候选 + 理由，默认只在"一枝独秀"时预选；写库一律 `verified:false`，
  玩家在实例页点一次关联才转 `true`（库面板的「关联到 CTM 地图站条目…」对话框也算人工确认）。
- **显示名与身份分开存**：`title` 是玩家右键「重命名」写下的名字，**优先级最高、且不参与分组键**
  —— `displayName()` 的顺序是 `title` → `chineseName` → `englishName` → 文件名，而 `groupKey()`
  只看 `hall.slug` / `englishName` / `chineseName`。所以改名永远安全：既不会把同组的几个语言版本
  拆开，也不会让已经关联好的组因为站上名字而改不动。
- 列表层级只靠字重与缩进：**系列行**（粗体 + 折叠箭头）→ **地图行**（粗体，一张图一行，行首「└」与系列箭头同列）；
  版本列只写 MC 版本、语言列只写中文/英文，**没有第二层子行**（具体语言与地图版本在导入对话框里选）。
  系列行默认收起，聚合四列（版本 / 语言 / 分类 / 已装张数）。三级右键
  （系列=展开与目录 / 地图=只改这张图 / 独立图=两者合一）；列宽存 `MapLibraryColumnState`。
  「重命名」在地图行与独立图上都有，「关联到 CTM 地图站条目…」是**顶层项**，不藏在二级菜单里。
- 实例名里的系列代码（`[US1]`）在网格里拆成名字下方一枚灰色药丸，文本由 `SeriesNames` 翻成站上系列名
  （`Ragecraft 3`）；**数据不改名**，表里没有的代码原样显示。

## 13. 上游同步

1. 每期结束 `git rebase upstream/develop`；冲突预期只在 `CMakeLists.txt` 与 `MainWindow.{h,cpp,ui}`。
2. 新增的 `World` getter 用**新方法名 + 默认参数**，不改旧签名 —— 上游改 `loadFromLevelDat` 时冲突面最小。
3. 设置项集中在 `Application` 构造函数里的 `m_settings->registerSetting(...)` 段（`launcher/Application.cpp` 约 660–985 行，按用途分块注释）。
4. 翻译不手改，走 `lupdate`。
5. 要独立二进制时再拆 `launcher_core` 静态库，**不要提前拆**。
