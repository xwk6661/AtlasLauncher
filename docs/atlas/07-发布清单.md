## 5. 发布动作（打 tag 那天）

```powershell
# 1) 版本号与产物
#    CMakeLists.txt 里 Launcher_VERSION_* 已是 0.1.0
cmake --build --preset win-local-release
powershell -File tools\package-windows.ps1 -Config Release

# 2) 冒烟：直接跑包里的 exe（不要跑 build 里的），确认版本 0.1.0、语言中文、能起窗口
# 3) 校验和
Get-FileHash dist\Atlas-0.1.0-win64-release.zip -Algorithm SHA256
```

- tag：`v0.1.0`（与 `Launcher_VERSION_NAME` 一致；updater 若启用会按这个比对）
- Release 附件：`Atlas-0.1.0-win64-release.zip` + 一行 SHA-256
- Release 说明至少写：**这是 0.1.0，未签名（SmartScreen 会提示未知发布者）**、便携版数据在 exe 旁、
  1.17/1.18 不能自动进图、问题反馈请附诊断包

## 6. 宣发口径（B 站等）

只讲三件别人做不到/没做的事，不要罗列功能：

1. **点一张地图，直接落进它的世界**（不是"又一个启动器"）；
2. **版本由程序从存档推断，判不出就拒绝导入**——顺手解释为什么不能用一个高版本核心通吃；
3. **≤1.19.4 也能直连**（Java Agent + 60 张符号表），这是绝大多数启动器不做的一段。

同时说清边界：只有 Windows 便携版、非官方、不含游戏文件、需要正版账号、
大厅数据来自 CTMMaps。

## 7. 与上游的"隔离"清单

目标：**基于上游、但作为独立项目存在**。界面上不出现任何上游站点，启动时不为品牌目的访问上游，
技术上必须依赖的部分保持并写清原因。

### 7.1 保留（技术必需，不是耦合）

| 项 | 位置 | 为什么不能改 |
| --- | --- | --- |
| `https://meta.prismlauncher.org/v1/` | `Launcher_META_URL` | 版本清单 / 素材 / 库的唯一来源。Atlas 没有自建元数据服务，改了就没有版本可装 |
| `org.prismlauncher.EntryPoint` | `LauncherPartLaunch.cpp:129` | 游戏 jar 里的 Java 主类名，改了启动不了 |
| `x-prismlauncher-*` | `modplatform/packwiz/Packwiz.cpp` | packwiz 的 TOML 字段名，是包格式规范的一部分 |
| `cmake/vcpkg`、`libraries/libnbtplusplus` 子模块 | `.gitmodules` | 构建依赖与 NBT 解析 |
| `files.prismlauncher.org/fmllibs/` | `Launcher_LEGACY_FMLLIBS_BASE_URL` | 只服务 ≤1.5.2 的旧 Forge，正常地图不会碰 |

| 安装器 URL 协议 | `prismlauncher://` | `atlas://` | 与上游启动器共存时不会互相抢注册（当前没有安装器，先对齐） |
| 更新器配置与排除表 | `prismlauncher_update.cfg`、`prismlauncher.exe` 等 | `atlas_update.cfg`、`atlas.exe` 等 | updater 未启用，先对齐 |

> **改这一类 CACHE 变量的坑**：`set(... CACHE STRING ...)` 只给新建的 build tree 用默认值，
> 已有的 `CMakeCache.txt` 会保留旧值 —— 表现是"代码改了但编出来的还是 Prism 的地址"。
> 换默认值之后要 `cmake --preset win-local -ULauncher_WIKI_URL -ULauncher_HELP_URL …` 清一遍。
