## 3. 五个环境坑（都已解决，按这个来）

| # | 坑 | 现象 | 解法 |
| --- | --- | --- | --- |
| 1 | vcpkg 的 git 注册表要完整历史 | 浅克隆卡在 63 MB | 把本地浅克隆当 **builtin 注册表**：manifest 加 `builtin-baseline`，`vcpkg-configuration.json` 用 `{"kind":"builtin"}` |
| 2 | vcpkg 要 pwsh 7.6.9 | 卡在下载 109 MB 的 zip | 16 线程分段下载 → 校验 SHA512 → 放进 `vcpkg/downloads/`；lzo / bzip2 同理从清华镜像取（哈希一致即可） |
| 3 | **VS 实例没注册 Windows SDK** | 端口构建报 `rc` 找不到、`LNK1104: kernel32.lib` | overlay triplet + `VCPKG_ENV_PASSTHROUGH RC LIB INCLUDE PATH` |
| 4 | 上游 Java 子项目用 `-source 7` | `不再支持源选项 7` | 预设里 `JAVAC/JAR/JAVA_EXECUTABLE` 指向 JDK 8 |
| 5 | **`Qt6Core.dll` 被复制到 exe 旁后找不到平台插件** | `no Qt platform plugin could be initialized` | 每次启动写 `Debug\qt.conf`（`Prefix=<Qt 根>`）并设 `QT_PLUGIN_PATH` |

坑 3 的关键：vcpkg 给端口构建的是**干净环境**，进程内改 `PATH`/`RC` 传不进去；而本机
`Enter-VsDevShell` 之后 `WindowsSdkDir` 是空的。overlay triplet：

```cmake
# E:/Program File/vcpkg-manifests/prism/triplets/x64-windows.cmake（不进仓库）
include("<仓库根>/cmake/vcpkg-triplets/x64-windows.cmake")
set(VCPKG_ENV_PASSTHROUGH RC LIB INCLUDE PATH)
```

**⚠ ABI 哈希**：`RC` / `LIB` / `INCLUDE` / `PATH` 都参与 vcpkg 的 ABI 哈希。`run-vcpkg.ps1` 与
`run-configure.ps1` 必须 dot-source **同一份** `env-toolchain.ps1`，否则每换一次环境就把 18 个依赖
重编一遍（11–20 分钟）。

坑 5 的机理（2026-11-10）：`run-atlas-debug.cmd` 为了让提权的 `atlas_filelink.exe` 也能加载 Qt，
会把 `Qt6Core.dll` / `Qt6Network.dll` 复制到 `Debug\`；Windows 先搜 exe 目录，于是 `atlas.exe` 用了
这份副本。Qt 6 按 DLL 位置反推 prefix，`Debug\` 不在 `<prefix>\bin` 下 → 插件目录算成空。
判据是 `QT_DEBUG_PLUGINS=1` 下的 `Could not find the Qt platform plugin "windows" in ""`。

## 4. 沙箱 / 自动化环境

沙箱会拦 `reg.exe`，导致 `vcvars64` / `Enter-VsDevShell` 静默失败（只设了 MSVC 的 `INCLUDE`/`LIB`，
没有 SDK 路径），随后 cmark 的 try-compile 挂在 `rc` 与 `kernel32.lib` 上，vcpkg 顺手清空
`vcpkg_installed`。两条绕过方式：

1. `build/_build_env.cmd`：手工写全 `INCLUDE`/`LIB`/`PATH`（SDK 在前、MSVC 在后）再 `cmake --preset`；
2. 直接跳过 VS 环境脚本，手抄 `env-toolchain.ps1` 的四个变量：

```powershell
$sdk = "C:\Program Files (x86)\Windows Kits\10"; $ver = "10.0.26100.0"
$vc  = "D:\Program Files\Microsoft Visual Studio\2022\VC\Tools\MSVC\14.44.35207"
$env:RC = "$sdk\bin\$ver\x64\rc.exe"
$env:INCLUDE = "$sdk\Include\$ver\ucrt;$sdk\Include\$ver\um;$sdk\Include\$ver\shared;$sdk\Include\$ver\winrt;$vc\include"
$env:LIB = "$sdk\Lib\$ver\ucrt\x64;$sdk\Lib\$ver\um\x64;$vc\lib\x64"
$machine = [Environment]::GetEnvironmentVariable('PATH','Machine')
$user    = [Environment]::GetEnvironmentVariable('PATH','User')
$env:PATH = "$sdk\bin\$ver\x64;$vc\bin\Hostx64\x64;$machine;$user"
& "D:\Program Files\Microsoft Visual Studio\2022\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe" --build --preset win-local
```

> **PATH 别随手拼**：它进 ABI 哈希。2026-11-15 用"当前 PATH 后接 SDK"跑过一次，哈希变了 → 6 个依赖
> 重编 8 分钟；换回上面从注册表重建的 PATH 后立刻恢复 `already installed`。
>
> 沙箱里 vcpkg 用 autotools 的端口（`lzo` 等）会停在 `-- Configuring x64-windows` 不动
> （`configure` 依赖 msys2 子进程，被拦）。把 `cmake --preset` / `--build` 放到沙箱外跑一次即可。

另一个反复出现的干扰：链接大文件（`LauncherTests.exe` 30 MB / `.pdb` 280 MB）时偶发
`C1083: Permission denied` 或链接挂起，重跑即可，**不是代码问题**；并行度越高越容易撞上，
连着失败时 `$env:CMAKE_BUILD_PARALLEL_LEVEL="3"` 再跑一次基本必过。

## 6. 产物与数据目录

`build\win-local\Debug\` 同时是**运行数据目录**：exe 旁有 `portable.txt`，所以 `atlas.cfg`、
`instances\`、`maps\`、`accounts.json` 都在这里。

> **不要对 `build` 目录做 clean** —— 会连玩家数据一起删。

### 6.1 资源库里有什么

| 位置 | 内容 | 缺了会怎样 | 判定依据 |
| --- | --- | --- | --- |
| `assets/objects/` | 素材本体，按 sha1 平铺 | 重下 | 文件在 + 大小一致 |
| `assets/indexes/` | 每版素材清单 | 重下（启动时本来会刷） | metacache + ETag |
| `libraries/` | 库 jar + 每版 client jar | 重下 | metacache |
| `java/` | Mojang 运行时 | 重下 | 目录存在 |
| `meta/` | 版本 json / 加载器元数据 | 重下 | metacache |
| `metacache` | **账本**：哪些库文件下过 | `libraries/` 整份重下 | — |

具体文件数与体积只在 [04 §5.4](04-进度与待办.md) 写一处。

2026-11-18 起本机两个启动器**共用一份库**：`D:\Games\PrismLauncher`（Prism 便携根，`SharedResourceDir`
指向它）。库由 Prism 持有、Atlas 借用；`meta/` 与 `metacache` 各在各的数据目录（Atlas 的在
`build/win-local/Debug/`，Prism 的在便携根）。当天把 Atlas 11-06 的整库备份并入并重建了两侧账本，
**26 个 Prism 实例与 10 个 Atlas 实例全部零缺口**（[06 §92](06-变更记录.md)）。

> **共用库的边界**：`assets/objects` 按内容寻址，两边直接认；`libraries` 一边一个账本，账本里没条目
> 就会重下 —— 下面规则 2 的「sha1 认领」**只有 Atlas 有**，上游 Prism 没有。所以共用一份库之后，
> 两边的 `metacache` 必须各自校准，只搬文件不改账本等于没搬。

三条规则：

1. **素材不需要账本**：判定是"文件在、大小对"，目录拷过去就认；
2. **库文件认账本，但账本缺失可以补**：条目缺失时先按元数据 sha1 核对本地文件，对得上补记录、跳过下载；
3. **账本不怕改路径 / 改时间戳**：存相对路径 + md5，base 启动时重算。

### 6.2 四种"换库"

| 想做的事 | 正确做法 |
| --- | --- |
| **整个库换盘 / 换机器（两启动器共用时推荐）** | 关掉两个启动器 → 把 `D:\Games\PrismLauncher` 整个搬走 → 改 Atlas 的 `SharedResourceDir`（Prism 跟 exe 走，不用改）→ 重启。两边账本存的是**相对路径**，不用重建 |
| 只挪 Atlas 的库 | 设置 → 资源 → 选目录 → **应用资源库**（搬三种资源；`meta`/`metacache` 留在数据目录）→ 立即生效，不用重启 |
| **做可迁移备份（留底 / 给别的机器）** | **连 `metacache` 一起打包**，只打 `libraries/` 等于白打；恢复见 `asset/AtlasResources-2026-11-18.说明.txt` |
| 整份拷给别的机器 | 复制 `assets/` + `libraries/` + `meta/` + `metacache`；`java/` 可选（不拷≈重下 500 MB） |
| 清空重下 | 删 `assets/objects`（连库一起重下就再删 `libraries/`）；`metacache` 可留 |

**别做**：把 `meta/`、`metacache` 塞进共享资源目录（它们按数据目录解析，塞过去等于没生效）。
Prism 的数据根固定在 exe 旁，**没有**「只把 assets/libraries 指到别的盘」的设置 —— 要分离只能做目录联接，
不建议（备份、换机器都会断）。

**账本是唯一必须随库走的东西**：`assets/objects` 按内容寻址，文件在就认；`libraries` 却要求「账本里有条目」。
上游 Prism **没有**「按 sha1 认领本地文件」这段（`Library::adoptExistingFile` 是 Atlas 的加料，见
[06 §70](06-变更记录.md)），所以只拷 `libraries/`、不带 `metacache`，Prism 会当成没下过、整份重下。
一份账本对两个启动器都成立：条目存的是**相对路径 + md5**，base 由各自启动时解析；解压后时间戳变了也
只是多算一次 md5（对得上就放行），不会重下。Atlas 即使没有账本也能用（走 sha1 认领，首次稍慢）。

拿官方启动器的 `.minecraft` 来用：Atlas 可以（按 sha1 认领），Prism 不行（没有认领逻辑）。

### 6.3 打包

```powershell
& .\tools\package-windows.ps1 -Config Release   # → dist\Atlas-12.0.0-win64-release.zip
```

前置：`build\win-local` 已 configure，且对应配置已经 build 过（Release 用 `--preset win-local-release`）。

产物是**便携目录 + zip**：`atlas.exe`、`atlas_filelink.exe`、Qt6 七个 DLL、`platforms/` / `styles/` /
`tls/` / `imageformats/` / `iconengines/`、`qt.conf`、`qtlogging.ini`、`portable.txt`。
包内**不含数据目录**：首次运行在 exe 旁自己建 `instances/`、`maps/`、`assets/` 等。
2026-11-15 实测：目录 42 MB，zip **18.6 MB**。

靠 CMake 三个 install 组件拼出来，**顺序不能反**：`Runtime`（exe）→ `bundle`（Qt DLL + `windeployqt`
插件，要求 exe 已在目标目录）→ `portable`（`portable.txt`）。五个坑：

1. **`Multiple conflicting paths found for Qt6Core.dll`**：`run-atlas-debug.cmd` 复制到 `Debug\` 的那两份
   要先删，否则依赖收集看到两个来源直接报错（脚本下次启动会自己再复制）；
2. **`".\atlas.exe" does not exist`**：只装 `bundle` 时 `windeployqt` 找不到 exe —— 见上面的顺序；
3. **`qtlogging.ini` 会掉到 `<仓库>\install\`**：那条 install 规则写的是 configure 时的前缀，不吃
   `--prefix`；脚本改成直接从 `launcher/qtlogging.ini` 拷，顺手删掉该目录；
4. **Debug 包不可分发**：链接的是调试运行库（`VCRUNTIME140D` 等），只在装了 VS 的机器上能跑；
5. **Release 包要自带 VC++ 运行库**：上游给 `windeployqt` 加了 `--no-compiler-runtime`（等安装器补），
   便携 zip 没安装器。脚本从 `VC\Redist\MSVC\<ver>\x64\Microsoft.VC143.CRT\` 拷 10 个可再分发 DLL。

冒烟：把目录拷到临时位置双击 `atlas.exe`，看到主窗口、`logs/Atlas-0.log` 里有
`Adjusted by: "Portable data path"` 就说明插件与路径都对（首次没有 `accounts.json` 的那条 Critical 正常）。

## 8. 仓库外动过什么（可撤销）

| 位置 | 改了什么 | 为什么 |
| --- | --- | --- |
| `…vcpkg-manifests/prism/vcpkg.json` | 加 `builtin-baseline` | 坑 1 |
| `…prism/vcpkg-configuration.json` | builtin 注册表 + 本地 overlay triplet | 坑 1 |
| `…prism/triplets/x64-windows.cmake` | 新增，透传 RC/LIB/INCLUDE/PATH | 坑 3 |
| `E:/Program File/vcpkg/downloads/` | 手工放入 pwsh / lzo / bzip2 源码包 | 坑 2 |
| `CMakeUserPresets.json`（gitignore） | ninja / rc / cl / JDK8 的绝对路径 | 坑 3、4 |
| `build/*.ps1`、`run-atlas-debug.cmd` | 一键复现 | — |

> **仓库目录改过名（`PrismLauncher` → `Atlas` → `AtlasLauncher`）时，仓库外这几处必须同步改**：
> `vcpkg-configuration.json` 的 `overlay-ports` / `overlay-triplets`、`triplets/x64-windows.cmake` 里的
> `include(...)`。仓库内脚本已按 `$PSScriptRoot` 推导。CMake 还会把旧源码路径写进 `CMakeCache.txt`，
> 改名后必须重新 configure。
